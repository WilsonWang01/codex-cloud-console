## 引导流程

1. 明确是否已有 AWS 账号/实例、使用本地还是长期服务、目标区域、预算、负载、入口及必须保留的数据。能从授权环境只读查到的信息不用重复问；不读取秘密正文，不擅自使用可能收费的查询 API。
2. 没有账号时，按指南解释注册路径、Free/Paid 计划与账单风险，引导用户本人完成邮箱、付款、验证码和 MFA。停在任何不明确的套餐/条款/收费确认前，不能代替用户接受。
3. 先考虑复用健康实例；新个人部署以 `t3.medium`、2 vCPU/4 GiB、40 GiB 加密 gp3、官方 Ubuntu x86_64 为评估起点。轻量试用与浏览器重负载见配置表。这不是免费承诺，也不是已做容量测试的保证。
4. 重新查阅官方 AWS 价格、免费计划规则与区域可用性；给出日期、区域、运行时长及包括 EBS/IP/网络/备份/模型的费用构成。资料冲突时说明不确定性，不替用户承受风险。
5. 输出变更清单和具体确认点，再执行已经授权的步骤。只读确认账号、区域和目标实例；检查运行中任务、服务、目录与备份。先确认保护措施可恢复，再进行任何有影响的变更。
6. 按仓库指南创建/连接/安装；SSM 优先。核实登录 Linux 用户与 systemd 服务用户，Codex 授权必须属于实际 worker，不能只确认本机已登录。
7. 先做无模型调用的健康、认证、目录和版本检查。真实任务、快照或额外资源测试需要对应授权；不为“验收”自动创建第二台机器。
8. 输出实际完成项、验证证据、未完成项、费用项、数据位置与恢复方法。没有执行则明确写“方案”，不能宣称已经部署。

## 必须守住的边界

- 所有可能收费或导致数据丢失的操作先确认，已有明确豁免只在原范围内有效。启动/扩容实例、增加磁盘/快照、购买域名、模型调用都不能从“研究一下”推导授权。
- 不默认创建/加入 AWS Organizations、Control Tower 或组织级 Identity Center。单 EC2 不需要它们；传统免费账号可能因此自动升级并失去赠金。已是新注册体验或现有组织时先核实适用规则，不擅自删除组织或改变套餐。
- 不承诺删除付款方式可以阻止账单，不承诺预算提醒是实时硬上限；停机、撤销凭据或改网络可能影响线上，先说明并确认。
- 人工 AWS 登录有过期时间；EC2 应用需要 AWS 权限时用最小权限实例角色。不要为了少登录而生成 root 或其他长期高权限访问密钥。
- 不索取、回显或提交密码、MFA、私钥、令牌；用户在受信任页面完成认证。不要读取 Codex `auth.json` 来证明登录成功，使用状态检查。
- 不复制全部工作 `CODEX_HOME` 充当个人助理隔离，不把控制台或云管理凭据传给任意命令 worker。不要宣传当前默认全权限运行方式可安全开放给不受信任调用方。
- 保留源码已有修改、工作区、worktrees、状态、附件、任务、Codex 历史与凭据；不能以“清理旧版本”为由删除这些数据。备份与恢复同样限制权限，涉及快照等费用先确认。
- 不运行不经检查的一键远程脚本；不因为健康检查失败就重装系统、重建实例、删除配置或放宽公网端口。

## 执行前确认模板

```text
将执行的具体操作及目标：
账号计划、区域、实例/磁盘与入口：
新增或持续费用，估算日期与来源：
现有任务/服务影响与维护窗口：
保留数据、备份位置与恢复步骤：
本次不执行的操作：
请确认上述范围；如信息不全，先补全，不执行变更。
```

身份不明、费用超出确认范围、数据位置未知、备份无法验证或文档与实际环境不一致时停止变更。失败后先只读诊断；重试不能隐式创建重复资源或重放有副作用的任务。
