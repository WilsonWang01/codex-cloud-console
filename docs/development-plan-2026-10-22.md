# Codex Cloud 下一阶段开发方案

状态：用户已确认完整方案，原生 goal 已启用；M1、A01 核心能力、A02、A03.1 JSON 及 A03.2b 私有结果/产物已发布 EC2/本机代理，线上 `a7c9324`；下一项 A03.2c 受限输入与真实独立客户端闭环。M2-M5 未完成。更新：2026-10-23，Asia/Shanghai。

本方案建立在[本轮现状分析](reviews/2026-10-22-next-stage-assessment.md)和[现有统一路线图](personal-agent-roadmap.md)之上。确认后作为下一阶段的执行顺序，保留旧路线图的需求和验收编号；历史报告继续作为证据，不重复开发已完成能力。

## 建议目标

把 Codex Cloud 做成自己可以日常依赖、外部受信任服务可以稳定接入的任务后端。完成标准是具体任务可重复交付、问题可恢复、状态与用量可信，以及手机上能够完成主要操作。

建议先完成三个阶段成果：**可靠性基线、可集成后端、日常个人助理**。移动交互、代码简化和上线验收贯穿每个阶段，最后进行连续七天观察。目标不是穷尽竞品所有功能。

| 使用方向 | 本阶段目标流程 | 用户得到的结果 |
| --- | --- | --- |
| 外部服务 | 提交研究任务，断开后继续查询，取得报告与图片/文件，取消或接收完成通知 | 不需要进入控制台才能拿到完整结果；请求、用量和错误能追踪 |
| 个人助理 | 打开今日，看到已授权来源的重要变化，形成草稿/下一步，确认后按允许范围执行并跟进 | 减少反复输入背景和从聊天里找结果 |
| 日常开发 | 从一个明确 Issue 形成隔离的开发任务、测试与 Review 结果，确认后发布 PR | 复用已有 GitHub 能力，保留人的发布决定 |

默认保留用户选定的 `gpt-6-sol / medium`；已有会话与定时任务的显式模型不批量覆盖。新模型由实际运行时发现与验证，不再靠页面硬编码升级。

## 第二阶段让后端真正易于集成

### A01 能力发现和接入契约

2026-10-23 已发布同一自动化范围的 `GET /api/automations/:id/v1/models` 和 `GET /api/automations/:id/v1/capabilities`，复用独立令牌；Caddy 精确 GET 路径和本机代理已验收，未暴露管理接口。状态、测试、数据保护及限制见 [A01 验收](acceptance/2026-10-23-api-discovery.md)。

能力描述至少区分文本、图片输入、图片输出、结构化结果、事件流、保存期限及不支持项，并包含 CLI/协议版本、最近探测时间。模型目录、最近成功执行、当前不可用是不同状态；列出模型不代表已证明账号能调用。

新增 OpenAPI 契约与可运行示例，优先 Node 和 Python。示例涵盖稳定幂等键、提交响应丢失、超时后取回、显式取消、文件下载和错误处理。普通 SDK 自动重试不能生成新业务键。无令牌/范围不符时，能力接口也不得泄漏其他项目。

本轮已完成发现/异步契约和 Node/Python 示例；文件下载示例明确依赖 A03 的受限产物接口，不以假接口满足验收。独立客户端已通过本机代理实际读取 EC2，真实 HTTPS 只读查询另行验证；本机 Node 直接域名连接有网络限制。生产页面内容和交互已读取，隐藏窗口导致线上截图未完成；七种本地视口测试不能代替真机。

验收：固定版本的 OpenAI/Anthropic SDK 合同测试，以及一个不导入服务器内部模块的外部客户端。未知字段、缺失能力及认证错误必须有明确结果。

### A02 独立任务与用量账本

2026-10-23 已完成并发布 A02.1：独立 SQLite 用量账本、去重和未知保留、UTC 预算合并、容量/覆盖信息、一致性备份和损坏健康门禁。原 JSON 任务状态保持；450 条明细裁到 200 后重启，统计仍保留全部 54,000 token。见 [账本验收](acceptance/2026-10-23-run-usage-ledger.md)。

A02.2 已发布 `3258e07`：新增外部任务/幂等同一事务、执行者/代次、有界队列、未领取恢复与已领取待核对、发布互斥和格式兼容回退。EC2 Node 22 的 25 项接收/恢复测试及 CI 全量通过，原 34 会话/200 运行和受保护文件保持。生产未运行模型重启演练；待核对任务暂无外部结案接口，队列能力字段仍待纳入发现接口。见 [任务队列验收](acceptance/2026-10-23-durable-external-tasks.md)。A02 核心要求已交付，不代表 M2 独立客户端交付闭环已完成。

现有自动化运行是第一版任务对象，保留其 ID、幂等键和接口。将接收、状态迁移、执行尝试、事件和用量的持久化逐步集中到一个单机存储边界。

推荐只对新增任务控制和计量采用 SQLite（单机事务数据库），不迁移 Codex 自身历史，不迁移所有个人资料，不引入外部数据库服务。实施前用实际 Node/EC2 版本验证驱动、备份和恢复；如果现有单进程实现能满足某一项验收，不为统一外观先行重写。

设计要求：

- 任务接收与幂等记录在一次事务中完成；相同输入重试返回同一运行，异体冲突明确拒绝。
- 待执行与执行中分开；领取记录有持有者和代次，旧执行器不能覆盖新结果。超出并发限制可以有界排队，队列满明确拒绝。
- 外部副作用未知时进入待核对，不自动再执行。不能承诺第三方动作全局“恰好一次”。
- 用量按调用方、运行、回合记录，重复事件不重复累计；运行明细裁剪不改变已保存汇总。未知用量保留原因。
- 先保持现有 UTC 日预算口径，界面明确时区；若以后改为用户时区，先规定边界迁移规则。
- 已有 30 天请求指标继续兼容；增加有界汇总、明细保留和容量指标，不把统计库做成永久原始日志仓库。

迁移必须在副本演练，校验 ID、数量、归属、状态、事件游标与已知用量。正式切换须停止接收新任务并确认空闲。若新版本已产生新数据，回退必须保留或转换这些数据，不能直接恢复旧快照覆盖。

### A03 结构化结果和受限产物交付

2026-10-23 已发布 A03.1 `e72f36c`：原生 outputSchema、受限 Ajv 校验、三种协议 create/parse、验证后流式返回及结果持久保存。CI、EC2 27 项接收/存储和真实 CLI 序列化通过；当前账号一次 `gpt-6-sol / medium` 原生 JSON 实测通过，14,467 tokens，无第三方写入。生产独立令牌链路、文件输入/产物下载和真实图片输出仍未完成；新临时令牌已询问授权但未创建。见 [JSON 验收](acceptance/2026-10-23-structured-output.md)。

为每个运行建立结果清单：结果状态、文本、结构化数据、来源引用、产物 ID、文件类型、大小、哈希、生成回合、有效期。完整文件仍存磁盘，清单不复制大段 Base64。

2026-10-23 A03.2a 已发布 `de6c2ec`：统一个人下载、原生图片和管理员本地回退的受限读取；Linux 目录句柄遍历、链接/读取变化拒绝、发送前完整校验及两份个人下载上限。CI、EC2 Node 22 的 12 项故障/边界测试和生产拒绝路径通过，原状态不变。此为前置加固，不是产物下载接口；清单、调用方/运行绑定、私有副本、存储/期限和受限输入仍待 A03.2b 及后续完成。见[读取基础验收](acceptance/2026-10-23-safe-file-read.md)。

外部调用方通过绑定其身份和运行的接口下载产物，不获得任意服务器文件路径。文件消失或过期返回明确错误；保留策略与幂等窗口协调，不能一边承诺重放，一边静默删除重放依赖。管理员下载、个人文件和 API 下载复用同一校验逻辑。

2026-10-23 A03.2b 已发布 `a7c9324`：[结果/产物验收](acceptance/2026-10-23-artifact-delivery.md)、[接入文档](artifact-delivery.md)。调用方/运行/原回合绑定、私有副本和下载、过期/容量/记录数限制、原键与副本协调、重启后读取及有界列表/计量补记通过本地与 EC2 35 项相关测试。CI、备份恢复、生产认证拒绝与原数据对账通过；34 会话、200 运行保持。任务格式升为 3，新数据产生后不能盲退旧执行器。一次观察请求 502 的根因仍未定位；未运行新的生产模型/令牌测试，截图仍受 0 宽窗口限制，真实文件/图片交付不写成已验收。受限输入与完整 M2 退出证据仍待补齐。

结构化输出先验证已安装 CLI 的 `outputSchema` 是否原生传递，再做服务端 JSON Schema 校验；失败返回结构化错误，不能把任意文字强行包装成通过。模型级输出限制做不到时仍明确拒绝，避免以截断响应冒充节省模型费用。

首批文件输入支持受限大小的文本、Markdown、静态图片；PDF 排在其后，通过受控解析或已验证的上游输入路径接入，显示解析失败/截断情况。文件上传需要调用方归属、数量/大小/存储上限与清理说明。远程任意 URL 抓取、音视频和客户端工具协议暂不进入首版。

图片输出沿用已有精确回合提取。补一次真实图像链路验证、清晰的不可用原因及文件交付；掩码、质量、尺寸等参数仅在上游可兑现后开放。图片工具可能独立计费，不能把文字回合 token 视作完整图片账单。

### A04 完成通知和 MCP 薄适配

完成回调采用持久投递记录、HMAC 签名（验证消息确由服务器发送）、事件 ID、时间戳、有限重试和失败记录。回调只投递最少元数据及鉴权查询路径，调用方按事件 ID 去重。所有回调失败后仍可轮询取结果。

回调目标由操作者预先登记，禁止每次请求携带任意地址；处理重定向、内网/元数据地址和 DNS 变化带来的访问风险。默认不发布匿名产物 URL。

在 HTTP 任务契约稳定后，MCP 只包装提交、状态、取消和产物查询，不建立第二套执行或审批引擎。先在一个可控制的客户端实测；Muse、Today、Grok Bot 的实际账号入口未验证前，不宣称已经接入其产品。

### A05 调用与用量页

2026-10-23 线上内容验收补记：首次同步会短暂显示默认示例自动化标签，后续应改为真实配置加载占位，避免创建令牌时造成误解；发现查询也仍缺独立中文汇总。与指标增强一并处理，不把这些未完成体验当作已验收。

保留已有服务、请求曲线和下钻，增加成功率、等待时间/执行时间、P50/P95（半数和 95% 请求完成所需时间）、失败类型、重试、未知用量比例、产物和回调投递状态。按服务设置并发、每日已知用量和有效期。

请求数、模型运行数、重放数分开；同一次任务重试不能重复计费统计。超时显示“前台等待结束，后台状态待查询”，不能直接写“任务失败”。金额只在有可靠账单来源时显示。

## 第三阶段形成日常个人助理闭环

### P01 有来源的今日简报

选择一个明确场景：**今日安排与待回复事项**。首版只读取已经授权的邮箱、日历及用户显式关注事项，生成少量需要处理的变化。

每条建议包含来源链接/对象 ID、读取时间、原始日期/时区、为什么现在需要处理、可执行的下一步。相同事件多次同步不重复提醒；无变化时不制造摘要；来源过期或读取失败时明确标示，不拿旧数据伪装新消息。

默认按需刷新，确认流程有效后才启用既有个人计划。连接器缺少可验证的只读约束时，先维持前台按需读取；不能因为提示词写了“只读”，就自动开放无人值守执行。

### P02 草稿和行动确认

先完整实现日程提案与邮件回复草稿。草稿可以编辑、驳回、稍后处理，并保留原始来源；在界面展示目标账号、对象、前后差异、参与者和可能影响。

授权绑定具体内容摘要和版本，修改后旧授权失效。发送、创建/修改日历等真实写入仍逐项获得用户确认；结果包含第三方对象 ID 和可重新查询的回执。超时没有回执时保持待核对，不自动重试。

先实现一个连接器的完整业务闭环，再复制到另一个。现有通用 MCP 审批继续复用；必要的独立业务动作适配必须有实际工具契约证据，不假定所有连接器都能被直接调用。

### P03 记忆治理与持续目标

扩展现有事实而不另造一套记忆引擎：用户事实增加来源、确认时间、可选有效期、启用状态；模型建议的新事实先进入候选，用户接受后生效。工作项目不自动读取个人事实。

删除或到期后停止新上下文注入，并清楚说明已有历史对话不会因此被抹除；需要继续长会话时处理旧上下文中的失效事实。记录实际引用的事实 ID，用户能够知道建议为什么产生。首版不引入向量数据库，也不扫描所有旧聊天提取私人信息。

目标复用已有关注事项与会话 goal，补里程碑、下一步、等待原因和结果关联。一个流程成功后可保存为个人计划，编辑输入、权限或完成条件后重新试运行。不会另造与现有 Routine 平行的调度器。

### P04 低打扰通知与手机使用

今日页优先显示“需要决定”“接下来”“最近结果”。历史活动折叠；跨日条目显示日期；测试任务采用显式用途标签和可恢复的隐藏，不删除历史。

移动端以交办、查看、确认、继续为核心：底部稳定输入区、键盘避让、附件上传进度、返回位置保留、失败不丢草稿、通知深链直达原任务。个人设置与运行时高级设置分层，连接服务在需要时展示授权解释。

通知沿用已有按通道投递与安静时间，补同一事件去重、过期摘要、送达与已查看分离。不会默认订阅用户设备。首版完成至少一部真实手机的键盘、后台恢复和通知流程，另一平台保留为明确未覆盖项。

### W01 开发流程的后续增强

在 API 与任务状态稳定后，完善 GitHub 授权状态与恢复引导、每 Issue 独立 worktree、测试证据和 Review 展示。无人值守筛选只匹配明确的仓库与标签，首次默认生成候选任务。

自动发评论、关闭 Issue、合并 PR 和部署生产不属于默认权限。已有发布预览与一次性确认继续使用。此项是本阶段的次优先事项，不阻塞个人与 API 两条主线达到首版目标。

## 架构和代码整理

```text
个人 Web / 工作 Web / 外部 HTTP / 后续 MCP
                    |
           身份与范围校验
                    |
         共用任务服务和能力检查
          /       |        \
       审批     结果产物     用量与投递
                    |
       Codex app-server 与受控连接器
```

保留单机部署和现有 React/Vite/Express。按实际修改拆分 `App.tsx` 的导航与会话状态、运行设置、个人首页；拆分 `server/index.mjs` 的运行服务和路由注册。每次拆分都有行为等价测试，不能同时重写全部状态管理、路由、设计系统和存储。

统一任务状态、错误结构、请求 ID、能力结果和产物描述。复用已有 `approval-broker`、`run-admission`、`model-api`、`personal-*` 模块。优先消除重复状态来源，文件行数只作观察，不作为为了拆分而拆分的验收指标。

不引入 Kubernetes、Redis、分布式队列、插件市场、自动自我改写或多 Agent 编排平台。共享账号继续满足现有使用偏好，但不会据此承诺隔离不可信租户。专用 worker 的强隔离或凭据代理另立设计和验证，不能复制主账号凭据冒充隔离。

## 验收标准

这些是拟定目标值，不是当前已达到的结果。每次报告记录设备、网络、数据规模、版本及样本量；只读测试和模型推理耗时分开。

| 维度 | 首版通过标准 |
| --- | --- |
| 任务恢复 | 同一键并发提交 100 次只接受一个运行；输入变化返回冲突；接收前后、领取前后、结果保存前后故障注入均不丢已接受任务 |
| 外部动作 | 未授权写入为 0；不确定结果不自动重复；一次具体批准只绑定一个确定内容版本 |
| 用量 | 250 条当日普通运行裁剪和重启后统计不变；重复回合事件不重复计量；未知用量一直可见 |
| API | 一个独立客户端完成文本/图片输入、结构化结果、文件下载、断线恢复、取消和回调；所有承诺字段通过 SDK/HTTP 合同测试 |
| 产物 | 跨调用方、越界、符号链接、过期和删除原文件均有确定结果；不会拿摘要或其他回合文件冒充交付 |
| 页面 | 30 次冷热打开/切换及受控断网测试无永久加载、串会话、草稿丢失；局部失败有下一步操作 |
| 性能 | 测定基线后，温缓存导航 P95 <=200ms；纯本地持久接收 P95 <=1s；冷首页有用内容目标 <=2.5s，外部探测不阻塞主体；无法达到时记录原因和下一步 |
| 个人流程 | 20 个预定义场景至少 18 个达到预先约定结果；关键授权与归属用例全部通过；来源过期不伪造新数据 |
| 记忆 | 接受、修改、到期、删除和跨设备冲突均有效；未确认事实不自动成为既定事实；工作会话不注入个人事实 |
| 手机 | 320/390/768/1280px 布局；至少一部真机完成输入、附件、确认、后台返回、通知深链；未覆盖平台明确列出 |
| 七天观察 | 每天有运行/无变化/跳过/失败的明确记录；无重复对外写入、无任务或草稿丢失；每条未送达通知可解释；用户评价至少 80% 已展示建议有用，样本不足则继续观察 |

P95 指 95% 的样本不超过该耗时。P0/P1 指可能造成严重安全/数据问题或阻断主要流程的问题。任何“通过”必须对应结果文件、截图、测试日志或真实业务回执；没有运行真实模型的模拟测试不能代替真实模型质量验收。

## 发布与资源边界

优先使用现有 EC2，不自动升级实例或添加 AWS 服务。每次发布前检查内存、磁盘和活动任务，备份并验证可恢复，构建候选版本，切换后检查页面及业务接口；只保留必要回退材料，业务数据清理单独评估。

本型分支与 main 的配套发布仍是独立事项，先核实两端版本顺序，不因本方案顺带合并或部署其他工作。源码、构建、部署和线上验证四个状态分别记录。

沿用既有已批准的 GitHub 推送、CI、持续模型额度和安全部署范围，不重复申请同一授权。新增 AWS 资源、新付费供应商、尚未覆盖的图片工具费用、数据删除或权限扩大须针对具体动作确认；邮件/日历写入按业务对象确认。额度重置始终需要明确授权。

模型运行采用有界验证：先模拟与协议检查，再运行最少数量真实用例；每次记录运行 ID、模型、耗时、已知 token 和未知部分。明确鉴权/权限失败后不连续烧额度重试；暂停依赖该服务的测试，继续独立开发。

## 延后范围

- 完整 OpenAI/Anthropic 替代，包括严格模型级 token 上限、所有采样字段、客户端任意工具、完整音视频和实时语音。
- 不可信多租户、团队权限体系、计费售卖和复杂供应商路由。
- 持久云浏览器与人工接管，直到确有高频任务需要、容量与登录边界明确。
- 健康、金融交易、购物支付等高风险主动执行。
- 大规模自动扫描全部邮件/聊天形成记忆，多 Bot 群聊和自主无限派生任务。

这些保留在长期待办，不影响本阶段有边界的完成。进一步投入前用实际任务价值和失败数据决定，而不只比较竞品功能清单。
