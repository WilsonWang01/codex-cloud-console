# 调用与用量

控制台左侧打开“调用与用量”，选择 24 小时、7 天或 30 天，再按调用方筛选。可切换提交、能力查询、结果查询和已知 token 曲线，展开分时表和最近请求，或导出同一筛选条件的 JSON。读取统计不会触发模型。

## 数字怎么理解

| 指标 | 口径 |
| --- | --- |
| 提交请求 | 已记录的新任务、续接及模型协议请求；包括被拒绝、等待超时和同键重放 |
| 受理任务 | 提交记录有关联运行 ID，且不是同键重放；同步调用超时也可能已受理 |
| 同键重放 | 复用原事件键返回原任务的调用，不是又运行一次模型 |
| 能力/结果查询、取消请求 | 与提交分别计数；查询或取消关联原任务，不增加受理数 |
| 调用错误 | 所有请求类别记录的错误状态，包括流式协议中的逻辑错误；不完全等同于网络 HTTP 状态或后台任务失败 |
| 任务记录 | 所选窗口内的调用方任务，使用持久用量账本与当前运行合并，不受最近 200 条任务明细限制 |
| 已观测模型回合 | 窗口内已取得会话 ID 和回合 ID 的去重数量；旧记录缺少标识不能据此断言没有执行，不是完整计费次数 |
| 任务成功率 | 已完成 /（已完成 + 明确失败）；取消、待核对、处理中、排队和未知状态不进入分母 |
| 未知用量占比 | 用量未知的终态任务 / 全部终态任务；进行中任务不算作丢失用量，未知也不计为零消耗 |

中断和需要核对的任务单独显示，不自动归入明确失败。等待超时或连接断开后，应使用原事件键恢复任务标识，再查询结果；不要换键重跑可能已有副作用的任务。

## 耗时与覆盖

P50 是中位数；P95 表示至少 95% 样本不超过的耗时，按整个筛选窗口的有效原始样本计算，不平均分时 P95。表中同时列出样本数；没有有效样本显示 `--`。

- 任务排队：接收时间到后台处理开始，只有同时存在两个时间且差值非负才计入。
- 后台处理：处理开始到明确终态，包含材料准备和收尾，不是纯模型推理。中断待核对时的恢复时间不能证明实际结束时间，因此不参与。
- 请求耗时：按提交、能力查询、结果查询和取消分组；无效或缺失的耗时不当作 0。
- 任务按处理开始时间归入窗口，尚未开始或旧记录缺少开始时间时用接收时间。曲线按浏览器本地时区显示，已有预算按 UTC 日期计算。

请求摘要扫描所选时间内仍保留的指标文件，逐行读取，仅保留最近 500 条明细；精确耗时分布占用随不同耗时值数量增长，不是常量内存或无限日志容量承诺。任务下钻最多 200 条，汇总不受该上限影响。

这些指标只覆盖**已记录的已认证调用**。鉴权前无法归属调用方的失败、部分限流拒绝不会记录；错误类别按记录的状态粗分，不能当作上游模型根因分析。指标文件被保留策略清理、损坏行跳过、读取期间文件消失或首次接入前历史已裁剪时，覆盖可能不完整。文件读取失败会明确报错，不把不完整读取伪装成成功。

token 仅累计完整的单轮快照，不重复叠加缓存及推理子项；不是 OpenAI/AWS 账单，页面不推算美元费用。账本保留最近 32 个完整 UTC 日及当天；请求指标约 30 天，详见[部署说明](setup.md#独立调用方)。

## 令牌与兼容

令牌只授权到服务器已加载的自动化，不使用首屏示例。输入调用方名称、选择必要范围后创建；明文仅展示一次，在自己的服务秘密配置中保存，不放在网址或仓库中。页面展示已撤销、已到期和有效期。撤销阻止后续请求，不停止已经运行的任务。

创建请求若超时或连接错误，结果可能已经保存。先刷新列表核对，必要时手动撤销多余令牌，**不要直接重复创建**；前端不自动重试创建。已显示的新令牌关闭前不能再次创建，避免丢失尚未保存的明文。

新版前端连接旧后端时，尚未提供的汇总和耗时显示 `--` 或明确缺失，不猜测为零。后台管理接口 `GET /api/clients/usage` 增加 `requestSummary`、`runSummary` 和 `missingMetricFiles`；它仍需管理员认证，不能用外部调用方令牌读取其他服务统计。`runBuckets.failed` 现在只含明确失败，另有 `unresolved`、`canceled`，导出数据的消费方需注意该口径修正。

本轮尚未交付按调用方配置的并发/每日限额 UI、产物/回调投递汇总；现有按自动化配置的限制、签名回调和结果查询继续生效。完整接入见[后端集成](backend-integration.md)。
