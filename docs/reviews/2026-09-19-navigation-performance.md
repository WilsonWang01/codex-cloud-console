# 页面切换性能优化 - 2026-09-19

基线：`c4664cf`。范围：前端项目和会话切换、草稿保存、聊天消息渲染；不包含后端协议改造或 EC2 部署。

## 瓶颈与修复

| 问题 | 修复 |
| --- | --- |
| Hash 路由与通知入口直接加载历史，同时又由路由 effect 加载一次 | 统一为路由 effect 加载；新项目与跨项目搜索结果沿用该入口 |
| 快速切换后旧历史请求及重试仍占用连接，旧 finally 可能清除新路由目标 | 使用 AbortController 取消过期请求与重试等待；只清理属于本次加载的路由目标 |
| 刷新会话对象时，goal/tokenUsage 的引用变化再次触发线程状态读取 | 状态读取只依赖项目和会话 ID；失败回退通过 ref 读取最新会话状态 |
| 切换时无变化的草稿也会发起 PATCH | 在原串行保存队列内比对已确认内容及版本；只有一致时跳过请求，失败后清除确认记录，真实编辑仍校验版本 |
| 跨项目 Hash 切换后又用新项目 ID 保存旧会话草稿 | 原项目负责保存一次，切换后的 handler 不再重复保存 |
| 输入与其他界面状态更新导致整段聊天 Markdown 重新解析 | 消息列表和消息行使用 React.memo；流式消息变更仍正常渲染 |
| 同项目切换等待云端期间缺乏反馈，输入仍可能写入旧会话 | 会话栏立即显示加载状态；加载期间禁用输入、附件与发送入口 |

## 实测

同一台本机、系统 Chrome、1440x1000 窗口，通过已有本地代理访问同一个线上后端。计时从点击或 Hash 切换开始，到目标会话显示；前后各一轮，数据用于定位，不是多轮统计或 P95 保证。

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 项目切换 A | 1281 ms | 872 ms |
| 项目切换 B | 1846 ms | 1711 ms |
| 同项目会话切换 A | 1310 ms | 795 ms |
| 同项目会话切换 B | 3310 ms | 1798 ms |

- 两次同项目切换平均耗时从 2310 ms 降至约 1297 ms，样本下降约 44%；单次仍受网络和云端负载影响。
- 每次同项目路由切换的历史 GET 从 2 次减少为 1 次，未修改草稿的切换 PATCH 从 1 次减少为 0 次；这两项另有可重复的 fixture 断言。
- 实测前后均未记录到浏览器长任务和页面运行错误；不能因此推断所有规模的会话都不存在主线程瓶颈。
- 优化后历史接口仍约需 0.65-1.76 秒。剩余延迟主要在网络与服务端读取流程，本轮没有通过展示过期历史隐藏它。

## 验收

- `npm run verify:local`：协议检查、7 项 normalizer 检查、TypeScript/Vite 构建、8 组回归、16 项安全测试。
- `npm run verify:safety:ui`：26 类浏览器场景，包括原有草稿和流式任务安全场景，以及新增 6 类导航性能场景。
- 120 条含表格、行内代码和格式化文本的消息：先使用 Chrome 精确覆盖率验证渲染函数确实执行，再对输入阶段单独计数；历史消息行渲染调用为 0。
- 慢请求期间连续切换：过期目标只请求一次，不重试、不覆盖新目标；会话栏显示加载状态且输入与附件选择处于禁用状态。
- 草稿保存覆盖：相同内容去重、附件变化、排队保存后撤回文本、冲突后重试、本机旧版本不能因内容相同跳过版本校验、跨项目保存归属。
- 桌面 1440x1000、手机 390x844 截图检查；手机长对话无横向溢出。测试使用隔离 API fixture，不发送真实模型任务。
