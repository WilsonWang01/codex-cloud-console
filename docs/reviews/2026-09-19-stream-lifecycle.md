# 流式任务生命周期 Review - 2026-09-19

审查基线：`4232415`。本轮接续草稿安全审查，聚焦聊天、Review、主动压缩和任务重连的异步状态归属，不代表全项目穷尽审计。

## 发现与修复

| 优先级 | 问题 | 修复 |
| --- | --- | --- |
| P1 | Review、压缩和任务重连只校验项目；切换同项目的会话后，旧事件仍可更新当前 token、目标或会话状态 | 四种流式入口共用订阅归属，离开会话时取消浏览器订阅；所有事件和异常必须仍属于当前订阅才可更新页面 |
| P1 | 旧任务无条件清空共享忙碌状态，可能把新任务误变为空闲 | 普通操作与流式任务分开管理；只有当前订阅可以释放自己的忙碌状态，旧请求的 finally 不再影响新请求 |
| P2 | 切换页面留下旧 HTTP 长连接，回到相同任务还可能被旧 job-id 去重锁挡住 | 以当前可见订阅替代共享 job-id 集合；旧连接及时释放，回到运行中的会话可以重新订阅；侧栏和会话列表允许切换运行中任务 |
| P2 | 重连传输失败后立即重新查询、订阅，可能产生请求循环；查询本身失败则不再重试 | 查询与订阅失败使用 1、2、4、8、16、30 秒退避，最高 30 秒；切换会话会取消等待中的查询 |
| P2 | 服务端重放历史事件，重复订阅时沿用上次错误消息，导致内容重复拼接或错误样式残留 | 每次重连重建该任务的临时消息，再应用重放事件；任务完成后以服务端会话历史为准 |
| P2 | 清理过期消息的 effect 在普通聊天运行时也执行，使生成中的消息提前失去 streaming 状态 | 清理行为直接依赖独立的流式状态，有活动订阅时不清理 |

## 设计取舍

- 新增一个小型 `ConversationStreamScope`，只管理 AbortController 和订阅归属，不引入状态管理库或修改后端协议。
- 取消 HTTP 订阅不等于取消云端任务。已核对后端 `subscribeJobEvents`：连接关闭只移除事件监听，不触发 turn interrupt。
- 不在本轮大规模合并各类事件解析器；Review、压缩等事件有不同业务含义，先共用生命周期这一处明确重复。
- 浏览器长连接测试独立到 `scripts/verify-stream-ui.mjs`，复用现有安全测试的 API fixture。
