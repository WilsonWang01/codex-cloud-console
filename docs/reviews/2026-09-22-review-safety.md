# Review 操作安全与请求隔离 - 2026-09-22

## 本轮修复

| 优先级 | 问题 | 处理 |
| --- | --- | --- |
| P1 | 还原全部未暂存变更时，按 HEAD 还原会覆盖工作区内的已暂存版本 | 改为从 Git 暂存区还原；兼容首次提交前及空暂存区，不改变 index，不清理被忽略的运行数据 |
| P1 | 文件、hunk、全部还原没有二次确认 | 三种粒度统一确认，明确项目、不可撤销风险；全部还原额外提示删除未跟踪文件和目录，取消不发送请求 |
| P1 | 快速切换变更范围或项目，旧快照可能覆盖新页面并被继续操作 | 快照绑定项目和视图，取消过期读取；刷新期间、读取失败后不允许应用旧补丁；项目切换重建面板本地状态 |
| P2 | 重复点击或操作中切换范围可能造成重复提交、错配结果 | 同步提交锁与按钮禁用共同保护；写入期间锁定视图，跨项目迟到结果不更新新页面；离开不擅自取消已提交的服务端操作 |
| P2 | PR 状态及远端 diff 的迟到响应串项目 | 取消旧读取并检查当前项目；同步 PR 期间禁止发布评论；不将其他项目的 Review 发现关联到当前文件 |
| P2 | 提供外部 AbortSignal 后，请求超时实际失效，主动取消又被误报为超时 | 合并两种取消来源，区分超时与主动取消，完成后清理定时器与监听器 |
| P2 | 只想查看 Review 却自动启动模型任务，另有固定 800ms 重复刷新 | `/review` 仅打开变更面板，显式点击“运行 Review”才启动任务；移除固定延迟和默认分支回填触发的重复读取 |
