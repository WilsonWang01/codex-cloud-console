# 会话与草稿安全 Review - 2026-09-19

审查基线：`a0130c1`。本轮聚焦会话切换、发送确认、草稿恢复及异步响应归属，包含修复与本地回归验证，不代表对所有功能的穷尽审计。

## 发现与修复

| 优先级 | 问题 | 修复 |
| --- | --- | --- |
| P1 | 消息或补充指令在服务端接受前清空输入，HTTP 失败可能丢失草稿；流式 HTTP 200 也可能只是初始化后立即报错 | Codex `turn/start` 成功后发送 `accepted` 事件；前端收到接受确认才清空原输入。旧后端以首次输出或成功完成作为确认。失败保留输入和附件 |
| P1 | 新建、切换、删除、分叉、归档、清空操作的迟到响应，可能回写已经切换到其他项目的页面 | 所有会话快照共用 `applyChatHistory`，校验项目与请求序号；过期响应不再更新当前对话、输入或模型设置 |
| P1 | 请求等待期间继续编辑，返回成功时可能清掉新内容 | 清理前比较提交时的输入与附件快照，只清理未改变的原始草稿；同一待接受请求禁止重复发送 |
| P2 | 草稿版本只在首次进入时记录，重新进入后仍使用旧版本，产生不必要的 409 冲突 | 没有未同步本机副本及进行中写入时，采用载入的版本；有本机修改或正在写入时保留原冲突基线 |
| P2 | 本机恢复的草稿被误标记为已经同步，历史刷新取消自动保存后不再补写 | 区分服务端载入与本机恢复，恢复内容重新进入自动保存流程 |
| P1 | 用户处理冲突期间继续输入，异步读取完成后仍用旧快照覆盖新内容 | 应用冲突解决结果前复核项目、会话及输入快照，发生变化时保留新输入并要求重新确认 |

## 简化

- 七处会话快照回写统一为一个入口，不引入新的状态管理依赖。
- 普通聊天的流式事件统一校验当前请求所属的会话视图，移除重复项目检查；过期事件不再切回旧会话。
- 提交锁使用请求自身的标识释放，避免较早请求结束时解除另一个正在提交的补充指令。
- 浏览器测试统一使用可配置的本地地址，修复其中一处写死端口的问题。

- `npm run verify:safety:ui`：11 类场景通过，包含跨项目编辑、迟到附件、草稿冲突、迟到会话响应、HTTP 发送失败、流式初始化失败、重复提交、提交期间新输入及成功清理。

- `git diff --check`：通过。

## 边界

- 未执行真实模型回合、生产 API 验收、EC2 发布或额度重置，未改动线上数据和任务。
- 后端仅增加向前兼容的接受事件；下次部署建议前后端一起更新。
- 没有修改状态文件格式、删除历史记录或迁移数据库。
- 大型单文件模块和全量 JSON 状态存储仍保留；后续应按独立功能逐步拆分，并基于实际数据规模决定是否更换存储，不在本轮引入大规模重构。
- Review、压缩及任务重连等其他流式入口尚未统一为普通聊天的请求生命周期实现，后续应独立补齐快速切换场景测试。
