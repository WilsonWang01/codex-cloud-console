# M2 按需 API 任务的受限执行策略

状态：候选代码与本机验收完成，尚未部署或为生产自动化启用。正式本机/EC2 仍为 `fb45f15`，原生 goal 保持 active；这不是 M2 独立客户端真实闭环完成证明。GitHub 检查以本分支关联 PR 的最终记录为准。

## 本轮范围

增加仅运营者可配置的 `workspace-restricted-v1`，沿用现有 app-server、工作树、任务队列和审批模块，不另建执行引擎。只用于没有系统定时服务的按需工作自动化；既有任务、模型、登录、个人空间和系统定时任务不自动迁移。

- 接收时把策略和执行副本同时保存；同事件键找回原任务，不用新策略重跑。
- 领取时比较原记录、执行副本和当前配置；移除、变更或损坏时拒绝模型启动。旧高权限会话不能直接作为受限上下文继续。
- 创建和恢复原生线程都禁用已配置连接器、Apps/插件、网页搜索和记忆；明确限制工作树写入、关闭命令联网及额外临时写入目录。
- 模型启动前核对实际线程 ID、规范目录、原生权限和完整连接器目录。目录缺页、重复、未知/启动中状态或额外工具均拒绝，不自动新建替代会话或放宽权限。
- 受限任务的权限申请直接拒绝，不进入人工批准队列；即使原生回合随后成功，运行记录也不会误标完成。
- 模型前失败明确记为未启动、0 tokens；已经尝试启动但结果未知的用量仍保持未知，不用 0 掩盖不确定消耗。
- `capabilities.execution`、`run.execution` 和 OpenAPI 提供可发现的边界；受限图片生成在接收任务前拒绝，既有非受限图片适配不变。

任务格式升级到 7，保留旧行、执行材料、幂等键及领取代次；增加不可变策略校验。回退只允许已知空库变更，非空库不能退回不识别策略的旧执行器，也不会通过恢复旧快照丢弃新任务。

## Review 与修正

1. 原生 `config/read` 不是可直接写回的配置：只传禁用表会丢 transport，整表写回又会把空值变成不合法的类型。现在只覆盖明确的启用键，保留原传输配置；无法安全表示的名称拒绝，不猜测解析方式。
2. 限制在原生返回中核对，不只检查请求参数。恢复时必须返回同一线程，不能把另一线程的安全状态当作原线程证明。
3. 限制检查失败不触发模型，却原本可能被写成未知用量；现在以实际 `turn/start` 尝试为边界。RPC 已提交后超时不会被标为零。
4. 旧工作树/旧策略、历史裁剪后的续接来源、任务格式回退和绕过 app-server 的系统定时服务都纳入核对；不增加第二套队列或全局默认权限迁移。
5. 回归测试最初未给模型适配接口传必需模型字段，断言落在输入拒绝而非策略拒绝；已修正，并确认没有模型启动。内存数据库重开测试改用同一测试时钟，避免把过期键误当幂等失败。
