# 个人计划来源失败的完整恢复验收

## 本轮缺口

基线 main `c1b2b36` 的 [PR #60](https://github.com/WilsonWang01/codex-cloud-console/pull/60#issuecomment-6541955694) 已修复只读工具失败被当作成功及旧确认复用，两轮准确 CI 均为 411/411、29 步成功。但原证据是“HTTP 试运行失败”和“调度存储暂停”两段，不能证明同一条已启用计划实际到点失败、重启保持并恢复。本轮只补原 E08 的这条集成证据，不新增产品功能或运行时模块。

## 同一条场景

复用既有实际控制台 HTTP 服务、调度器、持久流程/领取/任务/用量存储与模拟 Codex。所有文件位于独立临时根，服务只监听 `127.0.0.1`。只替换模型和连接器响应，不手写运行终态或领取记录，不修改系统时间，也不调用生产账号。

1. 创建一个虚构个人流程，真实 HTTP 试运行成功、明确确认结果，然后通过正式接口启用每天 UTC 计划。
2. 在模拟连接器层将同一来源改为不可读，保持任务正文不变。使用真实分钟边界和 30 秒调度周期等待领取。
3. 调度器只领取一次；工具失败即使伴随“来源读取完成”的模型摘要，实际任务仍失败。计划自动暂停、下一次运行清空、旧试运行确认失效。
4. 在任务已终态且计划暂停后停止并重新启动实际后台。流程文件逐字节相同、原失败领取保持、模拟 `turn/start` 次数仍为 2，没有重跑原事件。
5. 正式查询显示旧成功结果不可确认；重新确认旧结果与直接启用均返回 409。内置浏览器实际核对桌面、390/320px 刷新后的暂停、旧结果失效、无确认结果入口、禁止启用和无横向溢出。
6. 仅恢复模拟来源；新试运行成功，明确确认后可以启用。整个场景共 3 次模拟回合请求，没有隐式额外启动；最后暂停测试计划，保留本场景证据后关闭自建服务。

首次实际运行：试运行 10:03:47 UTC，计划设为 10:05:00，实际领取 10:05:16.669，持久暂停 10:05:46.660。重启后旧授权被拒绝，恢复后最终流程版本 8、处于暂停；原失败领取仍只有一条。原始 RPC 为 2 次初始化、3 次模拟回合请求、0 次账号登录启动、0 次直接连接器调用。后台自然转移及真实浏览器截图已保存；`--serve` 的人工验收等待时间不当作执行耗时或性能成绩。

## Review 与自动化门禁

- 只扩展既有 `verify-regressions.mjs`：增加一个集成检查和一个由私有文件控制的模拟来源失败。没有新增框架、服务器配置、权限或依赖；普通回归默认不进入人工等待。
- 分钟目标至少留 30 秒配置空间，实际暂停观察有明确超时；不降低产品的调度、预算、用量或版本保护。恢复必须重新试运行、重新确认，不重放失败任务。
- 进程清理复用原函数，重启前后逐字节核对状态，最终关闭计划和自建进程；只有临时测试根会清理，原有用户工作树及线上任务不接触。
- 独立选定场景已通过，语法与 `git diff --check` 通过；最终完整回归及准确候选/主线 CI 以本轮交付回执为准。集成组由 20 增至 21，不将单测 411 项误报为 411 个用户场景。

复现命令：

```bash
CODEX_CLOUD_REGRESSION_CASE='personal scheduled source failure pauses durably until a new approved trial' node scripts/verify-regressions.mjs
```

## 未覆盖与下一步

本轮不需部署，产品运行时代码与基线相同。此前待发主线的 EC2 费用预检确认仍未答复；生产 MCP 的完整限定许可、具体 HTTPS 回调目标、日历草稿 PR #52 的动作许可、真实邮件对象及真机/七天/真人评价仍按原门槛处理，不消耗或复用旧单次授权。没有 AWS、真实模型、第三方业务写入或本机安全设置变更。
