## 复现与实现

原 Python `Client.execute(..., wait=True)` 已将已受理运行编号打印到标准错误，但超时或请求失败抛出的异常没有运行、业务事件编号。调用程序如果只处理异常，不能可靠取得恢复依据，只能解析日志。提交响应丢失时也没有原业务事件编号属性。命令行最终错误行同样缺少这些编号。最初新增的三组检查全部失败，分别确认已受理编号为 `None`、未知提交丢失原业务编号和最终错误行缺少编号。

修复只给 `execute(...)` 的原有异常增加 `run_id`、`event_id`，不变更异常类型、HTTP 请求、重试次数或任务契约。恢复信息是每次调用的局部变量；只有归属和编号检查通过的响应才能更新已受理运行编号。命令行在最终错误行追加可用编号；没有已知值时不猜测、不创建新编号。底层 `request(...)` 不新增执行状态或本地持久队列。

异常仅停止本地调用，不隐式取消云端任务。业务侧仍须保存原输入、事件编号、运行编号、自动化与调用方身份：有运行编号就查询原任务；没有运行编号则用原事件编号和相同输入恢复提交。Python 实例的总期限仍从初始化计起，耗尽后使用新实例恢复，不重置云端额度或自动增加模型请求。
