# 取消保护版本的低空间安全发布

日期：2026-10-30，Asia/Shanghai。

## 结论

EC2 控制台已从 `98a1b4fbe48caca91b34c6740365035a4b569c28` 切换到准确候选 `1936ccb4f295b46ebed2b0988363fcf02cd86470`。本轮只发布已实现的取消保护，不部署当前 main 的其他功能，也没有升级或回退 CLI。本机代理随后激活同版本的既有已核验运行包，四个关键入口的校验值与 EC2 一致，严格健康通过。

原生 goal 已通过正式接口恢复为 active，当前原任务独立回读确认；原目标、创建时间和累计记录保留，没有新建替代目标、直接改写目标存储或重置额度。本轮发布不代表 M2-M5 已完成。

## 准备与 Review

- 复用该准确候选已有的 CI 和已授权完成的 Linux 检查，不再次消费单次 CPU 测试授权。原有失败、重试、检查结果及备份全部保留。
- 服务器可用空间约 1.21GiB，不执行整包依赖重装和前端构建。通过硬链接复用 4,105 个未变化文件、146,242,265 字节数据；10 个已审核变化文件采用独立文件加原子替换，不写穿旧程序文件。
- 1,059 个已跟踪源码逐文件核对通过，旧运行包全目录内容和权限未变。前端、代理及依赖锁文件没有变化，运行时只有已审核的取消逻辑变化。
- 11 项本地运行包保护检查覆盖旧程序及旧清单不变、已有目录拒绝覆盖、新文件、权限掩码、路径和符号链接边界。复用包内禁止原地安装、构建或修补文件。

## 备份与发布

- 检查原生请求、回合、压缩、来源读取、旧任务、持久任务、回调和自动化服务，未确认空闲就不停止控制台。
- 同时持有发布锁，临时限制本服务入口；停止控制台后才捕获最新状态，避免长时间在线备份期间发生缓存变化。没有向其他后台服务发送停止或重启指令。
- 对状态、个人目录及配置真实解包比对，单独生成一致的 SQLite 副本，并对恢复后的六张业务表及文件快照核对。旧程序归档先核对完整校验值、再与旧运行包逐文件比较后复用，不新增一份约 46MB 的压缩包。
- 第一轮在切换前中止：SQLite 返回的无原型对象与 JSON 读回的普通对象被严格比较误判。备份恢复已通过，程序未切换，旧服务自动恢复健康；没有拿备份覆盖生产数据。
- 先增加 JSON 往返用例复现，再在数据库读取边界将每行转换为普通对象；11 项停机和快照检查通过。新阶段和新备份使用独立标识，不清除旧阶段标记或改写失败回执。
- 修正后主操作约 14.2 秒，清理约 1.1 秒；这些是操作用时，不是精确的不可用时长。只切换程序链接，不修改原服务配置、原生配置、权限、任务格式或显式模型。失败保护只允许程序回退，不恢复旧业务快照。

## 上线后证据

- 严格健康 `strictOk=true`、`partial=false`；维护规则撤除且其他入口配置不变。
- 重启后及真实页面访问后，13 个受保护状态文件、4 个配置及六张数据库表核对一致。这次发布前后的 33 条控制台会话、200 条运行记录保持；个人目录和受限产物目录当时为空，不能据此宣称大量实际文件迁移已验收。
- 实际控制台原生进程仍运行 CLI 0.165.0；CLI 配置哈希保持。没有因默认模型调整覆盖既有会话的显式模型或推理深度。
- 97 个运行依赖与锁文件核对通过，生产依赖审计未发现漏洞。11 类公网管理、个人数据、会话和线程接口在未登录时均返回 401。
- 内置浏览器真实刷新既有对话，在线、已登录、20 条历史消息和原模型设置可见；调用与用量页完成加载，空窗口不伪造成功率或 Token 记录。私有截图保留，不将真实历史和凭据上传 GitHub。
- 页面后可用空间约 1.19GiB。备份、旧程序和原数据都保留，未执行空间清理或数据删除。

本轮主动模型回合、令牌创建、额度重置和第三方业务写入均为 0；不能推断其他原有后台任务没有正常消耗额度。本轮没有重验所有原生历史库记录，也没有完成真机或完整移动端验收。
