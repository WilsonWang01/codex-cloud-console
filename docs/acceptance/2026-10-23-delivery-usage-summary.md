## 实现与 Review

- 复用已有任务、结果、回调和用量账本，只增加只读汇总模块，没有新表、格式迁移、依赖或 AWS 资源。按同一调用方/任务窗口统计当前快照，不把投递发生时间与任务开始时间混用。
- 结果区分清单就绪、准备中、到期、未成功交付、无保留结果、历史未覆盖和待核对。未到期、成功且归属/回合/清单相符才计入就绪；中断不冒充成功，失败任务的清理不冒充交付到期。
- 汇总不读取文件正文或哈希验证字节，“清单就绪”不是实际下载成功证明。文件被外部删除后，保存元数据仍可就绪，下载接口会拒绝缺失文件；测试明确覆盖这一限制，不用统计扫描所有文件制造额外磁盘负担。
- 回调区分等待任务、等待投递、投递中/待恢复、接收端确认、失败/到期及没有保留记录。过期状态在读取时判定，不为查看页面触发清理或补发；2xx 不是业务完成回执。
- 回调领取次数和重复尝试分别统计，领取不等于已发 HTTP 请求，不计作模型执行/费用。无保留记录不宣称从未配置，历史未覆盖不按成功或失败填零。
- 汇总覆盖完整窗口，接口明细上限 200，页面最多 20；不返回提示词、结果内容、文件名/路径、回调地址/正文/密钥。管理员认证及回环信任边界不变，不新增公共路径或令牌权限。
- 复用原范围判断、筛选、导出、请求取消和过期响应保护；未提供新字段的旧后端显示明确缺失。紧凑摘要加原生展开，不增加一套任务页面或补发操作；复用原任务入口。

本轮由主执行者自查，没有独立 review agent。重点检查跨调用方泄漏、旧记录错误补零、清单与字节混淆、过期/失败误算、统计截断、读取引入写入或副作用，以及展开后的手机布局。当前未发现本单元 P0/P1，不以此承诺全项目无缺陷。
