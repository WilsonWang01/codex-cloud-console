## 变更与边界

- 统一个人文件主服务/专用 worker、原生图片保存路径以及管理员文件读取/图片预览的本地回退通道，复用同一受限读取方法，不增加依赖。
- Linux 通过持有的父目录句柄逐级打开子项，拒绝子路径中的符号链接、硬链接及非普通文件；读取前后核对文件身份、大小、纳秒修改时间和变化时间。没有可用的 `/proc/self/fd` 时失败，不静默退回路径读取。
- 文件先完整读取并校验，再发送正文；路径或内容变化时不把已读取的部分当作成功结果。路径限 4096 字符、64 段，避免请求打开无限目录句柄。大小沿用调用入口限制，个人文件默认 20 MiB，API 原生图片总计仍为 8 MiB。
- 个人文件预览/下载最多同时缓冲两份，读取完成但响应尚未结束也计入名额；请求中途断开不能提前释放仍在读取的名额。忙时 503 / Retry-After:1，慢响应两分钟后关闭。默认最多两份 20 MiB 正文，不代表整个服务内存被限制在 40 MiB。
- 正常 GET/HEAD、文件名和预览/附件头保持；不修改、移动或删除原文件。内部链接也不再作为可交付文件；需要交付真实普通文件。
- macOS 使用重复路径/文件身份校验，不具备 Linux 的目录句柄遍历保证；本机测试不当成不可信本地进程之间的隔离证明。生产目标是现有 EC2/Linux，仍不承诺多租户或同账号恶意进程隔离。
- 官方 app-server 的 fs/readFile 通道、文件写入、删除和列表扫描不在本轮重写范围，不宣称所有文件操作均已原子化。本轮没有添加新的公网 API 或匿名文件 URL。
