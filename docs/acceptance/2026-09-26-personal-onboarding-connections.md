# 个人助理引导、工作区权限与服务连接验收

## 问题与调整

旧实现将个人空间的执行策略强制改为 `read-only`，开发者指令同样写死只读，页面没有可写选项。因此截图中的描述是实现限制，不是账号掉线或模型能力问题。

- 默认仍只读，用户在权限菜单确认后可保存个人工作区内的文件。后端保留 `workspace-write`，拒绝继承全权限，审批固定为 `on-request`。权限变更在运行中被拒绝，不改变已启动任务。
- 个人助理使用面向调研、计划、邮件和文档的角色指令，区分当前能力与需要连接的服务；不宣称已经获得邮箱、长期记忆、后台提醒或本机设备权限。
- 新对话展示四类任务，已有对话提供任务建议入口。点击只填入草稿，不自动调用模型；替换已有草稿需确认。
- 新增服务目录，读取官方 `app/list` 全部分页，结合 `app/installed` 区分目录可访问与工具实际可调用。读取失败明确显示错误，不把旧状态伪装成可用。
- 授权入口仅接受服务返回的 HTTPS `chatgpt.com/apps/` 链接，用户在官方页面完成授权，返回后刷新状态。没有后台安装、自动授权、采集密码或复制凭据。
- 保留已有 MCP 连接入口，登录和刷新请求带项目范围，避免专用个人 worker 模式错误操作工作执行器。

## Review 边界

没有新建另一套 OAuth 服务、凭据库或个人账号体系。任务建议是轻量组件，服务面板按需加载，权限和项目归属沿用原有机制。

工作区写入由 Codex sandbox 执行；共享账号不是双向文件保密隔离。连接器授权可能影响同账号其他空间。外发、日程修改、删除和收费操作要求明确确认，但角色指令不等于独立的外部事务防火墙，不能替代上游工具策略与实际审批。当前没有新增附件上传或完整事务任务队列。

官方协议依据：[App Server 的 Apps 接口](https://learn.chatgpt.com/docs/app-server#apps-connectors)。目录和可调用状态仍受账号、上游服务及配置影响，不保证任意邮箱服务都存在。
