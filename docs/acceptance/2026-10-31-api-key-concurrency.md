## 原缺口与最小改动

上一轮 [PR #48](https://github.com/WilsonWang01/codex-cloud-console/pull/48) 已合并，准确主线 [CI 40989359789](https://github.com/WilsonWang01/codex-cloud-console/actions/runs/40989359789) 完整通过 407 项和 20 组 HTTP，材料/报告/重启下载已补齐。本轮重新取得主线并核对无新增提交；最初两次获取遇 HTTP2/TLS 错误，仅本次 Git 命令改用 HTTP/1.1 后成功，不改全局网络配置或关闭证书验证。

原存储测试只用两个进程，旧 HTTP 检查只并发六次，不能当作已经达到 100。修改现有 `verify-regressions.mjs` 的持久队列用例：为原来待取消的排队任务增加独立的虚构调用方，同一事件键和内容同时发起 100 个 HTTP 请求；保留输入缓冲、队列容量、权限、限流、原丢响应和未领取重启恢复检查。不另建服务器夹具、执行器、队列或压力测试框架。

## 实际过程与结果

使用真实 Express 后端、鉴权、任务 SQLite、取消、恢复与用量实现；Codex 是现有协议替身，不运行实际 CLI 或模型。服务只监听 `127.0.0.1`，所有仓库、令牌、文件与状态都在本轮自建临时目录，不复制共享登录。

| 检查 | 实际本机结果 |
| --- | --- |
| 旧基线 | 原定向用例通过，10.141 秒；不包含 100 次并发 |
| 100 次初始请求 | 同一调用方、原事件键和完全相同内容，以 `Promise.all` 并发发起；本机为 1 个 HTTP 200、99 个 `429 / input_buffer_busy` |
| 明确限流 | 每个忙响应的 `Retry-After` 都为 1；等待一秒，再分别有限次重试，不换键或内容 |
| 只接受一个任务 | 初始成功响应中只有一次新建；所有其他成功及 99 次重试都找回同一运行 ID |
| 实际持久化 | 重启前后分别直接查询 SQLite，独立调用方仅一条任务，原运行仅一条事件键 |
| 权限及取消 | 旧共享身份不能取消该独立调用方任务，返回 404；所属调用方取消成功，明确未执行、用量为零 |
| 重启与冲突 | 重启后原键仍找回同一 `canceled` 任务；改内容复用原键为 409，没有新任务 |
| 执行和用量 | 该调用方只有原任务一条用量记录、总量零；捕获的原生启动请求不含该任务。原夹具的另外两个替身回合仍各一次 |

这是**100 个并发提交的去重与恢复**，不是 100 个模型同时运行、100 个请求立即成功、生产压力测试或吞吐量承诺。99 个忙响应是原输入缓冲保护的实际结果，不通过扩大缓冲或取消限流来凑成功数；不同环境的成功/忙数量可以不同，但新任务和持久键始终必须各为一。
