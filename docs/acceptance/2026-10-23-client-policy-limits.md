## 实现与 Review

- 创建和编辑调用方可设置并发、每日已知 Token 及有效期。空值保持继承/不额外设限；并发不能突破既有服务器全局/单调用方上限，不改生产环境变量或旧调用方配置。
- 复用已有 JSON 调用方存储、SQLite 用量/任务、接收事务及运行槽位；没有新数据库、AWS 资源、依赖包或另一套配额记账。并发同时在持久领取和进程槽位检查，限制变严不会中断已有执行。
- 接收和执行前读取最新配置，覆盖异步、Heartbeat 及模型协议共用的提交链路；排队期间到期/撤销会阻止模型启动。自然日按 UTC 统计同调用方全部自动化，不清空账本、不操作账号额度；单次任务仍可能超出软阈值，不是金额硬上限。
- 待结算用量阻止进一步启动，未知终态要求核对，不按零处理。同键已受理请求先恢复原任务，即使之后达到限制也不重新运行；受理前拒绝不会预占事件键。
- 修复开启预算后的任务自阻断：执行检查排除当前任务和其他尚未开始的排队记录，不漏掉已经开始处理的任务。等待结算时保留原队列/事件键；达到限制等不再允许执行的任务明确结束且未启动用量为 0。
- 更新使用 `policyRevision/expectedRevision` 防止旧页面覆盖新配置；不允许改调用方身份或自动化范围，不复活已撤销令牌。冲突/结果不明保留表单输入，明确确认后才能载入最新值，不自动重复保存。
- 无效上限、到期时间、存储格式或重复身份失败关闭，不用默认空列表覆盖坏配置；严格健康新增调用方记录层。已保存非空限制时，发布回退检查拒绝不支持限制的旧后端，即使尚无任务数据库也不能绕过。
- 新管理接口仍位于 Caddy 网页认证后，未增加公网任务路径；后端回环地址及可信本机代理代表管理员权限，不声称内部端口有另一套 Bearer 管理鉴权。能力发现只带当前调用方的有效限制，不泄露其他服务用量。
- 表单复用原请求超时/中文错误、原 UI 结构和原生数字/日期控件；旧后端不提供限制元数据时不展示不可生效的配置入口。内部个人执行身份与独立 API 令牌区分，原个人计划仍通过既有权限门禁。

本轮是主执行者代码自查，没有独立 review agent。重点检查限额能否被绕过、模型是否重复启动、CAS 输入保留、失效认证、跨调用方预算、旧数据读取不写回、并行配置与回退安全。当前未发现本单元 P0/P1，但不据此保证全项目无缺陷或支持不可信多租户。

3. 同调用方待结算时拒绝再次受理；版本冲突不移除限制，更新限制后保留账本原数据，原拒绝键可重新申请受理。
