# 旧任务终态取消兼容

日期：2026-10-25，Asia/Shanghai。基线 `769aa58`，工作分支 `codex/legacy-terminal-cancel`。本项是 F04/M2 兼容修复，不是待核对任务自动结案、生产客户端闭环或整体目标完成。正式本机/EC2 仍为 `70b191f`，没有部署或重启。

## 复现与根因

已中断的持久任务由 SQLite 识别为终态，重复取消正常返回原记录；同状态的旧 JSON 任务却返回 409。共享取消函数的终态分支漏了 `interrupted`，旧格式记录随后落入“不允许取消”的拒绝分支。

定向真实 HTTP 检查在修复前以 `409 !== 200` 失败，日志 `/tmp/codex-legacy-terminal-cancel-red-20261025-r2.log`。不是仅按源码猜测，也没有给生产任务发取消请求。

原有“旧 cancelled 记录”检查只改了 JSON 镜像里的同 ID 任务；SQLite 中的原记录在读取时会覆盖该镜像，因此并未真正证明纯旧格式兼容。本次使用五个独立旧记录 ID，并先只读确认它们不存在于持久任务表，避免假通过。

首次扩展检查的跨调用方负例误用了此前已撤销的测试令牌，得到 401 而非预期的归属拒绝 404；改为在本轮私有夹具创建有效但不同归属的令牌，没有放宽为“401 或 404 都算成功”。修复前的产品错误由后续定向运行独立确认。

## 最小修复

只在共享取消函数的终态列表加入 `interrupted`。中断、失败、待核对等状态仍原样返回，HTTP 200 表示取消请求已处理，不表示任务成功或原有外部动作已撤销。

不重写旧记录、不迁移存储、不放宽归属校验，不新增模型执行、重试、结案接口或权限。未知用量保持未知，原事件、模型、完成时间及任务编号不改。

## Review 与边界

执行者自查，没有独立 review agent。核对归属判断先于终态返回、终态不进入中断 RPC、不将中断改为已取消，以及 SQLite 与纯旧 JSON 两条路径。保持当前排队/运行/取消中逻辑，既有回归继续覆盖实际中断确认后才进入取消终态。

当前能力接口已提供队列并发、调用方预算、有效期和执行材料限额，未重复开发旧方案段落中写为“待纳入”的能力。人工结案接口仍未实现；`needs_reconciliation` 保留原事件并禁止自动重放，不能为了清空警告而升级为成功或释放旧事件键。
