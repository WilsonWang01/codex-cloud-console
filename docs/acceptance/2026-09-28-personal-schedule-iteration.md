# 个人定时流程迭代验收

日期：2026-09-28。范围：个人流程的可确认定时、调度可靠性、手机端计划交互及与 Muse / Today / Grok Bot 的复评。

## 本轮实现

- 个人流程仍默认只手动运行。用户在流程详情选择每天或工作日、HH:mm 和 IANA 时区后，明确确认模型消耗才启用；可随时暂停，归档会关闭计划。旧 `personal-routines.json` 按原版本读取，不重置流程。
- 定时器先将触发领取和预分配的运行 ID 原子写入 0600 状态文件，再启动 Codex。每个计划运行有可查的会话与运行记录；同一进程重复 tick、重启或不明启动结果不自动重放。超过 10 分钟的错过窗口跳过，不补跑多次。
- 最多同时启用 3 条计划、每天 UTC 最多领取 3 次；已知自动化 token 当日达到 100,000 或用量不完整时拒绝新运行。单次最长 10 分钟，文件沙箱为只读并请求审批。额度限制是软门槛，无法约束单次最终模型费用；连接服务的写权限与文件沙箱不同，不能仅靠提示词保证外部动作不发生。
- 启动失败、执行失败、中断或结果待核对会自动暂停当前版本计划。用户改动版本后，尚未启动的旧领取不再执行。页面显示计划时区、下次时间、最近结果与暂停入口；“今日”可进入临近计划。

- `npm run verify:local`、`npm run verify:personal:ui`、`git diff --check`：通过。单元测试覆盖上海时间、纽约夏令时前后、无效时区、旧数据读取、并发领取去重、错过窗口、每日领取上限、启动失败暂停、重启后不明领取不重放及旧版本取消。

## 对标复评

对照 [Muse 的后台任务与活动透明度](https://introducing.muse.ai/)、[Today 的晨晚简报和跨应用跟进](https://today.ai/articles/blog/what-is-today)、[Grok Bot 的 Routines 管理与测试建议](https://docs.x.ai/grok-bot/skills-routines-and-automations)，本轮补上了用户可控的时间计划与可见记录，但**未达到竞品完整能力或真实使用成功率对等**。下一优先级是受控的邮件/日历变化发现、计划启用前的安全试运行、来源级游标与结果筛选、业务动作前的强制审批和真实手机通知送达。公开资料只能证明其宣称的产品能力，不能代替同账号实测。
