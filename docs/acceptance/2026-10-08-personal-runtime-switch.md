# 会话切换的设置归属保护（2026-10-08）

## 对标与范围

先读统一路线图及 10 月 7 日验收，重新核对 [Muse 产品设计](https://introducing.muse.ai/)、[Today 产品说明](https://today.ai/articles/blog/what-is-today)、[Grok Bot 流程说明](https://docs.x.ai/grok-bot/skills-routines-and-automations)。可见的权限控制、连续使用和流程验证是这些官方资料强调的方向；本轮把它们转化为一个基础验收项：切换对话时不能把另一条对话的设置展示或应用到当前对话。这是本项目的工程判断，不是已经登录竞品测得的差异。

只修复上轮实际页面暴露的一个缺口：加载期间暂显旧模型/权限且仍可打开设置；一并处理同一归属问题中的迟到保存响应。不扩展主动简报、记忆、连接器或浏览器服务。

## 实现与 Review

- 将已有历史加载与待导航标记用于设置可用状态，加载或目标未确定时显示“同步中”，不显示旧模型/权限，也不能选择设置。加载失败显示“暂不可用”，重新成功载入后恢复。
- 切换开始即隐藏并关闭已打开的模型、推理、权限和个人设置面板；按钮及指令入口禁用，同时设置处理函数拒绝加载中、待导航或旧会话回调，避免只靠按钮外观保护。
- 应用历史时，在同次更新中设置目标会话及其运行设置，避免加载完成第一帧仍显示旧值。直接打开对话链接的状态与引用采用同一个初始导航对象，修复原导航标记无法正常清除的问题。
- 保存响应核对项目、会话、历史载入代次及设置请求序号。切换到另一会话、离开后再回到原会话或已有较新保存时，旧响应不改当前页面，也不触发错误页的重新读取。
- 沿用现有状态、引用及请求序号；没有新增服务、依赖、存储或迁移，不修改默认模型、账号或授权。后端不变。两个并发显式设置请求的后端保存顺序仍不是本轮解决的问题。

## 本地验收

- 新页面测试先在旧代码失败，明确复现“同步中的个人会话仍可修改设置”。修复后 `npm run verify:runtime:ui` 通过，覆盖 320/390/1280px 的个人与工作空间。
- 验收包含慢速首次深链、已打开设置时慢速跳转、会话列表选择、加载成功恢复、旧保存响应在切换后返回、刷新保留各自模型，以及加载失败禁用和恢复。没有使用等待加载完成来绕过加载期间的问题。
- 新增两组设置处理函数测试：加载/导航/旧回调不执行更新；保存成功或失败在会话、项目、代次或请求变化后不能回写。返回同一个会话也按代次拒绝旧响应。
- `npm run verify:local`、`verify:personal:ui`、`verify:safety:ui` 通过，安全测试 33 组。首次完整回归有一项隔离测试缺少新引用，补齐测试环境后重新完整通过；不把第一次失败写成通过。
- 实际浏览器截图已人工检查手机及桌面：`docs/research/acceptance/runtime-switch-2026-10-08/{_personal,sample-app}-{loading,ready}-{320,390,1280}.png`。无页面脚本错误或整页横向溢出；可控 API 测试没有调用模型或第三方服务。构建仍有原有主包超过 500 kB 提示。
