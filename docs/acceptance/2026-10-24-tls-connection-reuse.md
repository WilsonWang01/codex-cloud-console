# TLS 连接复用与订阅释放验收

日期：2026-10-24，Asia/Shanghai。状态：候选实现和真实只读对照已有证据，最终回归、CI 和本机发布尚待收尾。EC2 与正式本机入口仍为 `8feedbe`；整体 goal 保持 active。

## 结论与范围

本轮不把外部网络重置归因到某一个尚未证实的设备。实际证据表明，原代理每次 API 都新建 TLS 连接，会放大约五秒握手重置的影响；有界复用能明显减少握手次数和本次样本中的等待。不是通过加重试、改 VPN、改系统代理、降低 TLS/证书校验或调整模型来掩盖问题。

本轮只计划更新本机转发组件，服务器后端、CLI、状态格式、模型和第三方权限不变，不需要重启 EC2。冷连接和其他网络故障仍可能发生，不能将有限样本的零失败当作永久可靠或整体 F02 根因已彻底修复。

## 对照证据

所有真实请求只读、不调用模型；匿名请求只核对预期 401，已登录请求只读既有 `/api/release`，不启动任务、不创建令牌、不读邮箱或日历、不发送邮件或修改第三方数据。

首次 HEAD 复用实验没有实际观察到复用，不能据此宣称生效；后改用生产常用的 GET 并检查真实 `reusedSocket` 和连接数。初次 40/40 的系统代理样本两组均成功，也没有被当作已经证明根因。所有失败样本均保留，没有只选最后一批成功结果。

参考 [OpenSSL 3.5 密钥组说明](https://docs.openssl.org/3.5/man3/SSL_CTX_set1_curves/)、[Node HTTP Agent](https://nodejs.org/api/http.html#class-httpagent) 与 [TLS 配置](https://nodejs.org/api/tls.html#tlscreatesecurecontextoptions)，并检查本机 Node 25.2.1 / OpenSSL 3.5.4 的实际实现。两组成功的匿名连接均保留可信证书验证，实际协商 TLS 1.3、相同密码套件和密钥组；没有为了测试绕过证书警告。

## 实现与 Review

- 普通请求、流式/模型请求使用两条标准 HTTPS 连接池，各最多 16 个活动连接，分别最多 4/2 个空闲连接，空闲最多 30 秒，并尊重服务器较短的存活提示；长订阅不能堵住普通查询。普通 HTTP 行为不变，没有自制 TLS 引擎、新依赖或额外网络服务。
- 页面断开时关闭对应转发请求、释放连接；正常结束不销毁已归还的连接。原有后端只移除事件监听，后台任务继续存在；不因此取消、重新提交或重跑模型。写请求在复用连接发生重置后仍只发送一次，结果不明继续待核对。
- 复用后的连接已就绪时不再追加永远不会触发的 `connect` 监听，避免内存/监听累积。异常记录增加布尔值 `reusedSocket`，就绪时间明确为本轮观测，不冒充新握手耗时；正常订阅关闭不额外刷异常日志。
- 转发固定到配置的协议/主机/端口，拒绝不同来源的绝对地址和网络路径，不能借入口把环境凭据带到任意主机。启动日志改为只显示入口来源，不打印 URL 的用户名、口令、路径或查询参数。相关回归含故意放入 URL 的模拟秘密。
- 执行者自查，未调用独立 review agent。没有新增代理选项、握手降级开关、自动重放写请求、复杂连接调度器或后台预热任务；之前试验但无充分收益的方案没有留在产品代码中。

## 自动化与待发布

新增真实 TLS 套接字回归覆盖：20 次请求共用一次握手；服务器关闭空闲连接后的恢复；不重放异常写入；31 秒活动流不被 30 秒空闲参数切断；24 个普通请求的连接上限；16 个长订阅不阻塞普通查询；20 次关闭订阅后不占用连接；拒绝不可信证书；日志不含模拟秘密、无监听数警告。后端实际订阅函数另有单元测试验证关闭只移除监听，不调用中断或重跑。

最终完整本地回归 293 项：290 通过、3 项 Linux 专用跳过、0 失败/取消，15 组隔离 HTTP 集成回归通过；纯运行包仍 97 个锁定依赖、103,376,234 字节。320/390/1280 相关 UI 回归验证中文原因/编号、原始敏感错误不外露、恢复后草稿仍在及无横向溢出，不是真实手机。最后一次源码审查之后重新完整运行，日志为忽略目录中的 `verify-local-shipping.log`。

CI、真实不可变新包验收、本机备份和生效版本、EC2 数据对账将在发布记录补齐。没有实际运行的项目不提前填写“通过”。
