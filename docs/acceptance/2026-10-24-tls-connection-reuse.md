# TLS 连接复用与订阅释放验收

日期：2026-10-24，Asia/Shanghai。状态：本机连接代理 `0400aec` 已生效，代码 CI 成功，正式页面恢复和数据核对完成。EC2 保持 `8feedbe`、未重启；底层冷连接重置仍有复发，整体 goal 保持 active。

## 结论与范围

本轮不把外部网络重置归因到某一个尚未证实的设备。实际证据表明，原代理每次 API 都新建 TLS 连接，会放大约五秒握手重置的影响；有界复用能明显减少握手次数和本次样本中的等待。不是通过加重试、改 VPN、改系统代理、降低 TLS/证书校验或调整模型来掩盖问题。

本轮只更新本机转发组件，服务器后端、CLI、状态格式、模型和第三方权限不变，没有重启 EC2。冷连接和其他网络故障仍可能发生，不能将有限样本的零失败当作永久可靠或整体 F02 根因已彻底修复。

## 实现与 Review

- 普通请求、流式/模型请求使用两条标准 HTTPS 连接池，各最多 16 个活动连接，分别最多 4/2 个空闲连接，空闲最多 30 秒，并尊重服务器较短的存活提示；长订阅不能堵住普通查询。普通 HTTP 行为不变，没有自制 TLS 引擎、新依赖或额外网络服务。
- 页面断开时关闭对应转发请求、释放连接；正常结束不销毁已归还的连接。原有后端只移除事件监听，后台任务继续存在；不因此取消、重新提交或重跑模型。写请求在复用连接发生重置后仍只发送一次，结果不明继续待核对。
- 复用后的连接已就绪时不再追加永远不会触发的 `connect` 监听，避免内存/监听累积。异常记录增加布尔值 `reusedSocket`，就绪时间明确为本轮观测，不冒充新握手耗时；正常订阅关闭不额外刷异常日志。
- 转发固定到配置的协议/主机/端口，拒绝不同来源的绝对地址和网络路径，不能借入口把环境凭据带到任意主机。启动日志改为只显示入口来源，不打印 URL 的用户名、口令、路径或查询参数。相关回归含故意放入 URL 的模拟秘密。
- 执行者自查，未调用独立 review agent。没有新增代理选项、握手降级开关、自动重放写请求、复杂连接调度器或后台预热任务；之前试验但无充分收益的方案没有留在产品代码中。
