## 用法和范围

个人空间的“今日”增加“今日日程”。进入页面只查看已保存的记录，点击刷新才通过已登录 Codex 的 Google Calendar 连接读取当天主日历，不运行模型。首次读取前不显示“今天空闲”；成功后展示账号、覆盖日期、时区、读取时间、来源链接及原日程时区。

记录超过五分钟、跨天/换时区或上次读取失败时，保留旧内容但明确标为待核对。最多两页、100 条，分页未结束显示部分覆盖，不据此判断空闲。刷新至少间隔 30 秒，同一时区同时刷新合并为一次读取；不同窗口并行请求被拒绝。多个已连接日历账号尚未提供选择器，会停止读取，不擅自挑选账号。

“规划今天”把当前完整、未过期的来源放入一个个人会话的待发送草稿，附对象 ID、版本、日期与读取时间；不会自动发送给模型，更不会修改日程。标题等外部内容标为资料而非用户授权。只覆盖主日历，不声称覆盖共享日历、邮箱、临时安排或真实可用时段。

连接沿用个人运行时及已有登录，不复制凭据、不新增第三方登录。公网仍经过原管理员登录，本机后端回环信任边界不变；不新增公共 API 路径或扩大调用方令牌权限。

## 对标与实现

本次重新读取 [Today 产品说明](https://today.ai/articles/blog/what-is-today)、[Muse 产品设计](https://introducing.muse.ai/) 与 [Grok Bot 官方概览](https://docs.x.ai/grok-bot/overview)。可借鉴的是打开即看到真实安排、来源可追溯、后台状态透明，以及外部动作前有明确确认。本轮只补“可核对的日程来源到个人草稿”，没有宣称已具备竞品的主动简报、跨应用闭环或真实移动端体验；没有登录竞品执行同题任务。

实现复用 `personal-*`、既有运行时、原子 JSON 写入、受限文件读取和当前草稿流程。没有新依赖、数据库表、后台定时器或 AWS 资源。浏览器的过期计时只更新显示，不读取第三方数据。

原生接入以服务器 CLI 0.157.1 实际生成协议和工具目录为准，参考 [App Server](https://learn.chatgpt.com/docs/app-server)；不是让模型理解自由文本再猜调用参数。固定可信服务器、Google Calendar 连接、已声明只读的 `google_calendar.search`，用工具实际参数 schema 校验固定主日历/日期范围，临时只读上下文没有 `turn/start`。拒绝任何额外权限或执行请求，结束后取消订阅；发布空闲门禁纳入来源读取。

事件按来源 ID 去重并计算内容版本，保留原始时间偏移；夏令时按真实本地 23/25 小时的一天处理，不按固定 24 小时硬切。来源链接只接受 Google Calendar 的 HTTPS 地址，超长地址不截成另一条链接。只存简短标题、时间、标识和链接，不保存描述、参与人等额外资料。缓存 0600、最多 1 MiB，读取防链接/超限/替换，损坏时停止且不覆盖原数据。

[Google Calendar 原生事件定义](https://developers.google.com/workspace/calendar/api/v3/reference/events)提供事件格式参考，但连接器非空返回格式必须以实测核对，不能用原生 API 文档替代真实连接器验收。

## 失败与未完成

初次集成断言错误地期待回环后端自行返回 401；实际管理员登录在公网反向代理，本机是受信任入口。已改为测试真实跨站边界，公网未登录拒绝留给发布验收，不为过测试临时改变登录体系。新增标题“今日日程”也使旧 UI 测试对“今日”的模糊匹配产生歧义，已改精确匹配。日程草稿测试一度污染旧夹具的会话序号，现恢复其独立测试状态。

完整回归首次发现旧审批测试抽取函数时缺少新增来源守卫对象，已补夹具并覆盖来源线程的额外审批拒绝；这不是线上授权放行。报告只记录最终实际跑过的检查。

发布前补充 review 发现本机代理原有 15 秒等待响应头小于来源读取的最大 45 秒加结束清理时间。只对固定日历刷新 POST 延长到至少 60 秒，保留其他请求限时和 POST 不重放规则；可信 TLS 代理测试验证超过普通时限仍能返回且只读取一次。尚未据此声称 F02 的历史网络重置已修复。
