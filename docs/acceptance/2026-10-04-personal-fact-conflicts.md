# 个人事实跨设备冲突保护（2026-10-04）

## 对标与本轮选择

重新核对 [Today 产品说明](https://today.ai/articles/blog/what-is-today)、[Muse 产品设计](https://introducing.muse.ai/)、[Muse 安全设计](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)与 [Grok Bot Skills/Routines](https://docs.x.ai/grok-bot/skills-routines-and-automations)。Today 强调跨设备连续性及可检查、纠正的个人记忆；Muse 强调可读写的记忆和确定性控制；Grok Bot 强调可重复流程及自动化前的验证。这些是官方描述，不是本轮竞品账号实测。

本轮只处理一个已复现的缺口：个人事实没有版本校验，手机的旧编辑或旧删除请求会覆盖电脑刚保存的内容。该问题会破坏后续个人任务的上下文，优先于添加更多未经验证的自动化。

## 实现与 Review

- 事实带有单调递增 `revision`，修改与删除必须提交读取到的版本；过期版本返回 409，缺少版本的旧页面返回 428，无效版本返回 400，已删除事实返回 404。拒绝请求不写文件。
- 原版 `version: 1` 数据中缺少 revision 的事实按版本 1 读取，不在读取时迁移；成功修改时增加版本，保留创建时间和原有附加字段。错误格式或重复 ID 的文件拒绝修改，不能当作空列表覆盖。
- 冲突界面读取并显示最新内容，保留本次未保存的输入。用户可继续编辑自己的修改或使用最新内容；选择后仍须点击保存，不自动重试写入。事实已删除时只能显式转为新事实草稿，不自动复活。
- 删除冲突后刷新列表，但不自动删除新版本；用户核对后重新确认。刷新按钮也不清空编辑器。冲突后的最新内容读取失败时保留输入并显示恢复错误。
- 沿用原 store 的串行操作与原子文件替换，没有新增服务、依赖、自动记忆抽取或第二套存储。Review 补充了空版本、长名称折行和旧回归用例的版本传递。

## 验收证据

- `npm run verify:personal-facts`：5 组通过。覆盖同版本并发修改/删除、重启后版本保留、缺失/无效/过期版本、旧数据只读不改写、损坏文件不覆盖、原子替换失败后安全重试，以及隔离真实 HTTP 后端的响应与数据核对。
- `npm run verify:personal:ui`：通过。两个真实浏览器标签页模拟两台设备，第二页保存后第一页面不能覆盖；两种冲突处理、删除冲突、事实已删除与读取失败均保留正确状态，没有自动写入。320/390/1280px 冲突截图及 44px 触控尺寸检查通过；原套件的 7 个视口、个人/工作切换、草稿和计划流程回归通过。
- `npm run verify:local` 与 `git diff --check`：通过。初次完整回归发现旧测试直接删除事实未传版本，调整测试请求后完整重跑通过，没有放宽生产校验。
- 截图：`docs/research/acceptance/personal-usage-2026-09-26/personal-facts-conflict-{320,390,1280}.png`。人工查看手机与桌面截图，内容与操作按钮未重叠、无整页横向溢出。
- 测试使用临时状态及假模型，没有修改生产个人事实、调用真实模型、发送邮件或修改日历。

## 停止前复评

| 对标目标 | 本轮后状态 | 尚需补齐 |
| --- | --- | --- |
| Today：跨设备可纠正记忆 | 旧页面不能静默覆盖最新事实，输入可在冲突后继续处理 | 带来源/有效期的记忆治理、跨来源主动发现、持续真实使用 |
| Muse：连续交办与动作透明 | 保留原事项/草稿恢复及审批，本轮提高个人上下文可靠性 | 真实连接器动作闭环、持久浏览器身份与人工接管 |
| Grok Bot：可验证可复用流程 | 原试运行门禁、时区、暂停与预算不变 | 事件触发、跨来源结果核对及更完整的长期任务恢复 |
| 手机交互 | 浏览器模拟冲突恢复通过 | iOS/Android 真机键盘、推送送达与弱网连续使用 |

这是单控制台进程的乐观并发保护，不是多个服务器进程共享 JSON 的事务保证；也不是事实修改历史或跨设备离线编辑同步。未保存编辑仍仅在当前组件内存中，不能宣称刷新或退出页面后保存。已经进入旧对话的个人内容不被追溯擦除。

整体能力与体验仍未达到有证据的竞品对等门槛；不停止后续对标续做。本轮发布证据另记下节。
