# M2 参考客户端的运行编号边界

基线 main `4d12003`。本轮仅修复 Node/Python 独立客户端，不改服务器、权限、依赖、存储或默认模型。原 goal 的正式恢复接口仍报告旧任务被本地会话占用；本轮按用户新要求人工继续，不新建目标或清空已有累计记录，也不宣称自动续做已恢复。

## 复现与修复

Node 原先只检查回执运行编号非空：含换行的编号仍会交给进度回调、恢复字段和后续轮询。手动传入的异常查询、取消或下载编号也会先发出已认证请求。Python 已检查返回编号，但手动传入的异常编号仍会请求服务器；单独的 `.` / `..` 也未排除。

先新增真实回环 HTTP 负例，`red-r2.log` 的两个测试均失败：一项实际得到 HTTP 404 而非本地拒绝，另一项缺少应有的无效回执拒绝。首次负例误用了长时间等待而中止，原 `red.log` 保留；只去掉负例不需要的等待后取得确定复现，没有改产品通过门槛。

复用各自一个小型编号检查：状态、取消、结果和下载入口先拒绝空白、控制字符、路径分隔符、超长编号及单独的点路径；Node 在调用进度钩子和记录返回编号之前也核对。保留已有允许的字母、数字及 `_.:-`，不替换合法编号或已有恢复上下文。异常回执保留原事件键，不继续查询、不取消、不换键提交。

自查补了尾部 LF/CRLF，避免 JavaScript 正则结尾锚点把末尾换行误当合法；删除 Python 输出分支已被入口覆盖的重复检查。没有引入共享 SDK 框架或新的依赖。仅执行者 review，没有独立 review agent。
