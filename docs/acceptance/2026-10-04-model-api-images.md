# 模型协议图片输入验收与 Review

## 完成范围

- OpenAI `image_url` data URL、Anthropic `image.source` Base64 输入；PNG/JPEG/WebP，user 消息混合文本、多图及历史图片。
- 图片按消息顺序编号，通过 Codex 原生 `image` 输入发送；prompt 与运行索引只包含图片描述和内容哈希，不复制 Base64 或新建附件缓存目录。
- 8 张/请求、4 MiB/图、8 MiB 解码总量、12 MiB HTTP JSON、64 KiB 转换文本限制；编码与 MIME 文件头基础检查，真正解码由 Codex 处理。
- 同事件换图返回 409，幂等重放不运行第二次模型；既有认证、隔离执行、用量与文本 SSE 契约不变。
- README、SDK 图片示例、部署指南及配套 Skill 同步，明确图片数据留存与未支持的其他模态。

## Review 与修复

1. **大正文先认证**：增大 JSON 上限前，先验证目标自动化的令牌权限，再缓冲正文；接收任务时再次检查。回归检查暴露了全局中间件缺少路由参数的问题，改为挂载在带自动化 ID 的路径后通过。
2. **图片不是文本**：Base64 不拼进 prompt；序号与哈希保留原消息归属，实际图片在原生输入里顺序对应。原文本请求的 prompt 格式保留，既有幂等摘要不因这轮升级变化。
3. **拒绝隐藏控制失效**：真实 CLI 的模拟 provider 检查发现 detail 虽出现在 schema，却没有转发到模型请求。只接受省略/auto，对 low/high/original 明确 400；不做虚假的质量或 token 预算保证。
4. **避免历史膨胀**：原 normalizer 会把 image URL 全文当聊天文本。内嵌图现在只显示“内嵌图片”，不会把 Base64 再复制到控制台历史。Codex 自身原始历史仍可能留存输入。
5. **不引入抓取与文件读取**：远程 URL、本机路径、file ID、SVG、GIF、音视频和 PDF 内容块失败关闭；不以本轮兼容为由新增任意下载器或第三方模型账户。

结构上扩展既有协议模块，给原任务传入仅由该模块产生的图片输入。异步任务 API 没有新增可绕过验证的图片字段；生产不新增依赖、不更改状态 schema。

## 验收证据

- `npm run verify:local`：最终版本通过；包含构建、schema、认证、隔离任务、恢复、计量、个人空间与 GitHub 等全量回归。
- `npm run verify:model-api`：14 组通过；两套官方 SDK、图片顺序/正文哈希/换图冲突、格式/体积限制、错误终态与流式收据。
- `npm run verify:regressions`：9 组通过；真实 Express、假 Codex、真实隔离 Git 工作树；捕获 `turn/start` 原生图片块，认证先于超大 JSON、持久化索引不包含原图、无效图不新建任务。
- `npm run verify:model-api:codex`：本机 Codex CLI 0.160.0 通过。独立临时 HOME/CODEX_HOME、本机 HTTP provider、虚构令牌；捕获真实 `input_image` 和原图 data URL 后返回刻意的非重试错误。这验证序列化，不是成功模型回合。
- normalizer 检查：原上传附件不回归，内嵌图片不复制 Base64。
- `git diff --check`：通过。既有主 chunk 502.19 kB 提示仍在；本轮没有前端布局改动，不宣称新增手机/桌面视觉验收。

## 客观限制

只补齐图片理解输入，不是完整多模态 API；图片/音频生成、音视频转写、PDF、远程图片下载与客户端工具调用尚未适配。输出仍为文本。模型是否可用、是否支持图片及真实识别效果由账号与 Codex 后端决定。

未调用付费模型、没有第三方写入，也没有为验收读取或复制已有 Codex 登录凭据。不将模拟结果称为真实图片理解质量验收。原小时任务失效路径另行处理，本轮不恢复其持续模型消耗。
