# 个人助理外部操作可靠性迭代

日期：2026-09-27。本报告记录本地代码和模拟验收；真实 EC2、付费模型和第三方业务写入须另行授权后验收。上一轮线上证据与局限见[个人助理对标迭代验收](2026-09-27-personal-agent-muse-today-iteration.md)。

## 本轮结果

| 路径 | 实现及证据 | 边界 |
| --- | --- | --- |
| MCP 写入开始后超时或中断 | 对 `readOnlyHint: false` 的 MCP 调用立即持久化待核对状态，90 秒无回执时中断回合；失败会话阻止直接重试，排队消息暂停 | `readOnlyHint` 缺失或标注错误的工具不能据此识别；MCP 之外的 shell/网页写入不在此机制内 |
| 写入成功与失败 | 所有写入工具有完成回执且回合成功才自动清除；工具失败但模型回合成功仍进入待核对；多次写入逐项记录服务、动作和状态，不保存参数 | 工具报告完成不等于第三方业务已验收；无法自动判断远端是否已创建或删除 |
| 用户核对 | “今日”列出待核对会话；对话显示风险说明和可展开操作清单；用户在第三方服务核对后显式确认，过期确认 ID 返回冲突 | 确认只代表用户已核对，不会自动补偿、重试或证明外部结果 |
| 后台任务 | 同一执行链上的自动化遇到不确定 MCP 写入时，运行记录进入 `needs_reconciliation`；同键重放返回原运行，不重新执行 | 尚未证明不同入口间的事务级恰好一次；真实跨天运行仍待验收 |
| 移动端 | 320px 顶栏操作改为带名称和提示的图标，核对按钮独占一行；320px/390px 浏览器模拟无横向溢出，刷新后提示仍在 | 尚未在真机、弱网或真实外部服务中验证 |
| 个人计划任务 | “今日”把同一次会话的外部写入、排队和自动化异常合并为一个待核对入口；无会话异常和未来计划可直达个人计划页，运行历史保留待核对状态 | 仅能管理已配置的计划，不能由用户新建带时区、预算和错过运行策略的 Routine |

验证：`npm run verify:local`、`npm run verify:personal:ui`、`git diff --check` 通过。模拟 app-server 覆盖只读、写入成功、无 App 上下文字段、超时、工具失败、阻断重试、过期确认和人工确认。浏览器模拟覆盖“今日”进入对话、刷新后保留、逐项展开、320px/390px 布局和确认后消失；截图在 `docs/research/acceptance/personal-usage-2026-09-26/`，包括 `external-review-320.png` 与 `external-review-390.png`。测试没有调用真实模型或修改第三方数据。

补充模拟验收覆盖：同一会话的三种待核对信号只计一次；个人计划页只列个人任务、没有 Git 同步操作，320px/390px 无横向溢出；手动运行取消额度确认后没有发出运行请求。按需任务不显示无效的暂停按钮；独立自动化提醒可由用户核对后标记已读，刷新后仍保持已读，但原始运行记录不被改写。个人计划页截图为 `personal-routines-320.png`、`personal-routines-390.png`。当前计划页使用已有自动化配置，没有新增计划或改变定时器。320px 截图边缘有重复顶栏图像；页面 DOM 仅一条顶栏，视口底部命中测试也未发现第二条，推断是浏览器截图合成现象。

## 停止前对标复评

| 用户期望 | 当前判断 | 下一门槛 |
| --- | --- | --- |
| Muse 的持续目标、活动透明与外部动作监督 | 有会话目标、运行记录、审批及本轮外部写入待核对；仍是多个分散入口 | 在真实任务上把计划、动作、回执和产物串成一个可追溯结果 |
| Today 的跨来源主动简报与日常连续性 | 有用户维护的事实/关注事项、有来源的内部变化和默认关闭的提醒；没有邮件/日历变化检测 | 经授权读取外部来源，验证去重、过期与低打扰推送，再评估连续使用体验 |
| Grok Bot 的可复用流程与跨天 Routine | 已配置的个人计划可从“今日”和侧栏打开，定时计划可暂停，按需计划不会出现无效控制；可查看运行记录，手动运行及恢复前确认模型费用；仍不能由用户创建 Routine | 实现可确认的创建/编辑、时区、预算与错过运行策略，并完成真实跨天验收 |
| 手机快速交办和确认 | 主要路径已适配 320px/390px；本轮压缩核对提示，修复顶栏裁切 | 真机与弱网测试、实际第三方授权/确认路径的可用性测试 |

对标仅依据公开说明：[Muse 产品设计](https://introducing.muse.ai/)、[Today 产品说明](https://today.ai/articles/blog/what-is-today)、[Grok Bot Skills 与 Routines](https://docs.x.ai/grok-bot/skills-routines-and-automations)。没有登录竞品执行同一任务，不能宣称成功率或整体能力相等。本轮降低重复动作风险，但**没有完成竞品对等**；下一优先级是真实 Calendar 只读/写入的受控回执、跨来源主动发现、长期任务中途恢复和移动真机验证。
