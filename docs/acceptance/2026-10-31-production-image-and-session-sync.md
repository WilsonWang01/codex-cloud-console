## 页面后发现的 P1 问题

用量页实际筛选本次调用方：提交 2、受理 1、同键重放 1、已知 token 34,289、模型回合 1、处理中 0；1280px 桌面和 390px 手机尺寸均能查看，后者没有横向溢出。原生图片端点在内置浏览器实际加载，手机尺寸展示完整图片；不是实体手机证据。

但直接打开本次自动化对话后，页面回退项目，显示没有对话。随后对账发现旧 API 验收会话的索引缺失，不能把这一页面记为成功，也不能宣布数据保持。

根因在 `syncAppServerThreads -> upsertAppServerThreads`：`thread/list` 按项目目录筛选，且最多读取 120 条；工作树目录不等于项目根目录，分页也不是完整历史。代码却把没有列出的已有线程视作删除，直接移除其本地会话索引。这会使历史入口、显式模型和空草稿的索引不可达。用户主动归档、删除是另一条流程，不能由列表缺项推断。

首次页面前对账还发现一条旧去重键被移除。其到期时间为 `2026-10-30T18:31:50.418Z`，早于本次执行，符合既有 24 小时缓存策略；原任务和私有结果仍在。这项正常过期与随后发生的索引缺失必须分别记录，不能用过期机制解释或忽略丢失的会话索引。

## 最小修复与 Review

- 移除按列表缺项隐式删除索引的分支和无用选项，所有增量、搜索、通知和正常同步共用原合并路径。
- 保留明确的归档通知和用户删除流程；不新增权限、存储格式、后台修复引擎或自动清理机制。
- 列表仍最多展示原定数量，已登记的历史元数据不因过滤或分页而被删。明确归档/删除负责整理索引，不用隐式删除换取空间。
- 新单元先在旧代码上复现：工作树、旧页会话被删且活动项改变；修复后空列表、失败列表、增量合并均保留旧会话、草稿、显式模型和其他空间。
- 复用原 HTTP 端到端用例，真实后端接收成功空列表后，自动化会话仍在；服务重启后仍可找回索引并下载原报告和图片。定向 34.016 秒通过，不调用真实模型。
- `npm run verify:local` 通过：408 项，405 通过、3 项 Linux 专属跳过、失败 0；`verify-regressions` 的 20 组全部通过，另 GitHub API 集成通过。Linux 与当前 CLI 完整检查仍以准确头 CI 为准，不把本机跳过项写成通过。
- 仅执行者自查，未另开 review agent。重点核对所有调用处、明确归档/删除、有限目录与分页、队列和草稿、原回合私有结果及重启行为；没有借机扩展前端或连接器范围。
