# 个人提醒补发顺序验收（2026-10-01）

## 对标与范围

复核 [Muse 安全设计](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)、[Today 产品说明](https://today.ai/articles/blog/what-is-today)、[Grok Bot Skills 与 Routines](https://docs.x.ai/grok-bot/skills-routines-and-automations)。Today 强调少量影响当天的主动提醒；Grok Bot 建议给无人值守流程明确陈旧数据处理规则。本项目上一轮把个人到期提醒的补发窗口扩至 7 天，但每轮最多发 5 条，原排序却让最早逾期的旧事项先发，可能压后刚到期事项。

本轮仅将补发候选改为按到期时间由近到远排序。7 天窗口、安静时段、每项去重、失败重试和每轮 5 条上限不变；未启用新推送或第三方连接。

## 验收与代码审查

- 单元测试将输入倒序排列，验证 7 条积压事项的前 5 个候选为最近到期者；同时验证补发边界、已完成排除及推送内容不含私有事项名称。
- `npm run verify:local`、`CODEX_CLOUD_SAFETY_UI_URL=http://127.0.0.1:18787/ npm run verify:personal:ui` 均通过，后者覆盖个人提醒设置和 7 个桌面/手机视口。
- 只读打开实际本地代理的个人今日页，确认云端在线、历史会话和已有待核对动作仍在；390px 视口页面 `scrollWidth` 为 390，无横向溢出。未点击会创建、发送或清除数据的控件。
- 代码审查确认通知发送端仍按候选顺序取前 5 条，持久送达记录仍由既有 ID 去重。相同到期时间保留原有稳定顺序；没有更改存储格式或现有用户数据。

## 限制与发布状态

- 线上当前没有到期关注事项；真实浏览器推送顺序和离线设备到达率未验收，不能从本地测试推断生产已生效。
- 与竞品的事前连接器权限隔离和真实账号任务成功率仍无对等证据。
- 本轮和之前的本地提交尚未推送或部署。发布须等待明确授权，再重新确认任务空闲、备份并校验、严格健康检查和失败回退。
