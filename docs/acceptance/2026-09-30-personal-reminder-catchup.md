# 个人提醒断线补发验收（2026-09-30）

## 对标与选择

复核 [Muse 安全设计](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)、[Today 产品说明](https://today.ai/articles/blog/what-is-today) 和 [Grok Bot Skills 与 Routines](https://docs.x.ai/grok-bot/skills-routines-and-automations)。这些产品重视持续跟进和受控通知；本项目的个人关注事项虽有到期推送，但逾期超过 24 小时即从候选中消失。设备或服务离线一天以上后，用户可能永远收不到原定提醒。

本轮只修这个缺口：已开启个人提醒的推送订阅，可在到期后 7 天内补发。沿用现有按事项 ID 与到期时间去重、安静时段及每轮最多 5 条的发送逻辑；超过 7 天的旧事项不推送，避免长期积压突然打扰。不会自动启用提醒或发送邮件。

## 验收与审查

- 单元测试覆盖 2 天逾期仍可补发、7 天边界、超过 7 天/已完成不推送、私有标题不进入推送内容。
- `npm run verify:local` 全部通过；`CODEX_CLOUD_SAFETY_UI_URL=http://127.0.0.1:18787/ npm run verify:personal:ui` 通过，含移动端提醒设置和 7 个视口检查。
- 只读打开实际代理的个人今日页：云端在线、历史会话仍在、当前待核对的 TinyFish 动作仍在，没有操作或清除它。生产当前没有关注事项，因此不能把页面检查当作真实推送交付验收；没有发送任何推送或运行模型。
- 代码审查：补发只改变候选时间窗，不改推送设置、订阅、持久去重键和通道重试；既有 `100` 项个人事项上限及每轮 `5` 条限制仍生效。没有改变任何用户数据。

## 未完成与发布状态

- 真实设备长时间离线、浏览器通知权限撤销、推送服务故障的到达率未测。7 天后仍逾期的事项可在今日页查看，但不会补发推送。
- 与 Muse、Today、Grok Bot 的真实账号任务成功率及事前连接器权限隔离仍未对等。
- 当前改动仅在本地，尚未推送 GitHub 或部署 EC2；前一轮本地安全变更也仍待发布授权。发布前须重新检查任务空闲、备份并校验、严格健康检查及失败回退。
