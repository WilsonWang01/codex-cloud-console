# 个人事项关联失败后的刷新恢复（2026-10-02）

## 对标与范围

复核 [Muse 安全设计](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)、[Today 产品说明](https://today.ai/articles/blog/what-is-today) 和 [Grok Bot Skills 与 Routines](https://docs.x.ai/grok-bot/skills-routines-and-automations)。竞品都把持续任务及可恢复执行作为个人助理体验的一部分；本项目的“关注事项 → 起草个人对话”若先建会话、再关联事项时失败，原本仅在当前 React 页面保留会话 ID。刷新后再次起草会新建对话，导致同一事项出现重复草稿。

本轮只修复同一浏览器标签页的刷新恢复：待关联的事项 ID 和会话 ID 同步保存在 `sessionStorage`；关联成功或事项被删除后移除记录。仅保存 ID，不保存事项标题、正文或聊天内容。存储不可用时仍保留原有页面内重试能力。

## 验收与审查

- Playwright 真实页面用例模拟关联接口临时失败，确认失败时待关联 ID 已同步存储；刷新后出现“重试关联”，复用原会话且不新增第二个会话；成功后清除临时记录。测试夹具补齐了会话选择 API，使刷新后的跳转按现有接口契约执行。
- `npm run verify:local` 与 `CODEX_CLOUD_SAFETY_UI_URL=http://127.0.0.1:18787/ npm run verify:personal:ui` 均通过，后者仍覆盖 7 个视口和手机事项操作。
- 只读查看实际代理的个人今日页：云端在线，已有个人会话和待核对的外部动作保留；390px 视口 `scrollWidth` 为 390。没有创建真实事项、会话或运行模型。
- 代码审查：未修改后端存储格式、原有会话或第三方数据；恢复记录最多读取 100 条且限制 ID 长度。失败记录只在当前浏览器标签页的会话存储中保存，不写入云端。

## 限制与发布状态

- 新标签、其他设备、浏览器清理会话存储或用户删除原草稿后，不能保证复用原会话；这是本地恢复，不是事务性跨设备任务绑定。跨设备闭环仍需后端幂等创建/关联服务。
- 竞品级事前连接器授权与真实账号任务成功率仍无对等证据。
- 本轮仅本地提交，未推送 GitHub 或部署 EC2；发布仍须明确授权、检查运行任务、备份校验、严格健康检查及失败回退。
