## 实现与边界

- 异步 webhook/heartbeat 接受明确的 `attachments`；文件名称、MIME、编码、大小和内容摘要严格校验，不上传目录或接受任意服务器路径。材料作为独立原生文本/image 数据块传给 Codex，不混进会触发文件/Skill 提及解析的主请求。
- Responses 接受受限文本 `input_file`；Anthropic Messages 接受纯文本 `document`。Chat 的 txt/md 文件块、PDF、远程 URL、文件 ID、音视频、引用坐标及缓存字段明确拒绝，不冒充全协议兼容。
- Node/Python 独立客户端增加 `--attach`、`--input` 和 `--prompt`，只读取用户明确给出的有界普通文件；未导入服务器内部模块。格式约束和产物请求可与材料一起提交。
- 名称、顺序和内容摘要参与原事件键核对；同键不同材料 409。元数据只保存序号、名称、类型、大小与哈希，不复制全文或 Base64。领取后重验摘要，材料变化时在启动模型前失败。
- 先鉴权再读 JSON；只支持未压缩 application/json。接收缓冲全局 2 份、每调用方 1 份，正文最多 12 MiB、连接 30 秒。忙时 429 并提供 Retry-After，接收结果不明仍按原事件键恢复，不盲目改键重做。
- 完整执行材料按实际序列化字节限制：每任务 12 MiB、全局 128 MiB、每调用方 32 MiB，与任务/幂等记录在同一事务接收。拒绝不留下任务或占用幂等键；同键重放不重复占空间。
- 排队材料重启保留；明确终态后清除执行载荷，已领取丢失仍待核对、不自动重跑。取消或模型前失败的交付状态改为失败，不永远显示等待交付。

文本每份 64 KiB、合计 128 KiB、最多 4 份；图片每份 4 MiB、合计 8 MiB，全部材料最多 8 份。图片只做现有编码/文件头检查，完整解码交给 Codex。没有新增包依赖、上传目录、对象存储、第二套队列或公开文件路径。

上述是输入和逻辑存储限制，不是进程内存、整机磁盘或模型费用硬上限。材料分块不等于防提示注入沙箱，原工具权限仍须审核；不能据此向不可信租户开放。数据库空闲页复用不等于物理擦除或立即缩小，原生历史和现有备份不被自动清除。

实际 HTTP 加模拟 CLI 覆盖：txt/Markdown/PNG 到原生输入、材料不触发 Skill/文件扫描、Responses/Anthropic 官方固定 SDK 格式、未知字段拒绝、客户端显式读文件、错误 UTF-8/超限/FIFO、同键材料改变、排队重启保留、篡改摘要拒绝和终态清理。这些是协议/接收证据，不是生产模型阅读材料质量的证明。

缓冲故障测试包含 malformed JSON、gzip/大小/Content-Type 拒绝、慢连接、断开、超时和接受中断开：底层接收未结束时仍保留名额，不能通过反复断开积累无限未完成接收。已鉴权的前置拒绝计入原请求类别，模型用量不被伪记为已执行。

第一次全量回归在原有“同调用方六个并发 POST 全部 200”的旧断言失败；新有界缓冲按设计返回 429。修正测试为核对具体 `input_buffer_busy`、Retry-After 及同键重试只产生一条任务，之后全量通过，没有宽松接受任意错误。原失败日志保留。

Review 重点修正：附件文本经过主 prompt 提及扫描、同步模型等待保留大请求体、调用方断开过早释放未结束接收、排队材料缺少持久容量上限、预模型失败仍显示等待交付。复用 SQLite 事务、现有接收/计量与图片校验；没有为材料另建服务框架。生产依赖包加载通过，26,393,928 字节，无新增依赖；主前端包约 505 kB 提醒仍存在，不称已优化。
