## 实现

- 新增同一自动化范围的 `GET /api/automations/:id/v1/models`、`GET /api/automations/:id/v1/capabilities`。仅接受独立调用方令牌，不接受控制台免登录或旧共享令牌替代其身份。
- 返回模型目录、推理档位、CLI/协议版本、图文与事件流能力、限制及留存边界。模型在目录中不等于账号已成功执行；执行证据仅来自同一调用方和自动化的保留记录，失败记录也不直接等于模型不可用。
- 上游未提供模型创建时间和所有者，OpenAI 列表子集使用明确说明的 `created=0 / owned_by=unknown`，不伪造官方元数据。
- 请求先鉴权再读目录；缺令牌、错误范围、冲突凭据、未知参数、限流和上游不可用都有明确结果。与结果轮询共享每分钟 60 次上限。
- 能力查询单独计量，不增加已接受的模型请求数。没有新增一套状态存储。
- Caddy 只增加上述两个 GET 路径；本机代理保留调用方自己的认证头，不注入共享管理令牌。其他路由保持不变。
- Node/Python 示例不依赖服务器内部模块，包含发现、稳定业务键、提交、轮询、超时、显式取消和拒绝跳转。Python 使用标准库，无新增依赖。
- OpenAPI 3.1 覆盖 2 个发现接口及 4 个异步任务接口；不宣称它是全部模型适配协议的完整规范。Anthropic 使用通用 GET 查询自定义能力，不宣称兼容其 `models.list`。

接入入口见[后端集成](../backend-integration.md)、[模型适配](../model-api-adapters.md)、[OpenAPI](../openapi.json)。
