# 只读浏览不产生虚假会话活动（2026-10-05）

## 对标与本轮选择

本轮重新读取路线图和 10 月 4 日验收，并核对 [Muse 产品设计](https://introducing.muse.ai/)、[Today 产品说明](https://today.ai/articles/blog/what-is-today)与 [Grok Bot Skills/Routines](https://docs.x.ai/grok-bot/skills-routines-and-automations)。Muse 强调可见的后台活动以及有意义的变化才打扰用户；Today 强调跨天连续性和反映真实变化的首屏；Grok Bot 强调可验证的重复流程。仍未登录竞品执行任务，官方描述不等于对等验收。

只选择上次登记的一个 P2：`GET /api/chat/sessions` 与 `GET /api/codex/thread-state` 刷新运行时，会把会话 `updatedAt` 改为读取时间。没有新消息的旧对话因此可能上浮到最近列表，也会重复写入聊天文件。这影响“继续对话”和侧栏排序，并非发现了错误发送提醒或第三方写入。

## 实现与 Review

- 沿用 `updateSessionRuntime`，增加内部 `touchActivity` 选项，默认保持原有主动修改行为。只读运行时刷新显式不更新时间；没有活动任务的设置通知同样保留原时间。运行时观察改用 `thread/read` 的模型与推理字段，不再通过 `thread/resume` 恢复线程或修改个人权限。
- 真实模型、权限等设置仍可同步，待下一轮应用的模型与个人工作区权限逻辑不变。变化的设置可以落盘，但不能伪造活动时间；没有变化时复用原 `mutateChatStore` 的内容比较，不再重复写盘。
- 发送消息、完成运行、显式修改模型/目标/标题、外部动作待核对等写入仍按原逻辑更新时间。官方线程优先采用专门用于最近排序的 `recencyAt`，而非包含加载/元数据更新的 `updatedAt`；列表、读取、启动通知和导入复用同一转换。新活动仍按官方事实源同步，不能倒退用户刚做的本地修改；旧 CLI 缺少 recency 字段时才回退到 metadata 时间。
- 没有新增存储、服务、依赖或迁移，也不回填旧时间。历史已被只读操作改变的时间无法凭当前数据可靠还原，不根据猜测改写会话。
- Review 核对所有调用点，未把 `makeActive: false` 全局误当作只读。新增测试使用现有 VM、临时 HTTP 后端与浏览器套件，没有为了小修复拆出第二套会话服务。

## 验收

- 定向安全测试先在旧代码上失败，复现时间变化；最终 4 组通过。覆盖无变化不写盘、有变化仍同步但保留时间、错误项目不写入、草稿/当前会话不变、显式修改仍更新，以及个人权限/待应用模型、失败和活动任务路径；观察请求必须是 `thread/read`，官方活动时间与较新的本地修改均得到保留。迟到的官方读取在串行写入队列内再次保留较新活动，不能用旧快照覆盖刚完成的任务时间。
- HTTP 回归覆盖真实 `thread-state` 读取前后完整聊天状态一致，以及显式改模型后时间更新、再读取时待应用模型与时间保持。初次用例暴露 fixture 的权限为空而服务同步为默认值，补齐 fixture 的真实预期设置后完整回归通过；未阻止正常设置同步或放宽生产校验。
- `npm run verify:local` 通过；安全测试共 29 组，原任务、审批、模型 API、事实并发、事项/计划、提醒、GitHub 等回归均通过。构建仍有原有主包大于 500 kB 的提示，不宣称本轮解决首屏加载性能。
- `npm run verify:personal:ui` 通过。新增 320/390/1280px 浏览器路径：较新对话排在较旧对话之前，打开旧对话、刷新、返回今日，列表文字/时间及次序不变，无整页水平溢出、无脚本错误。原套件的 7 个视口、草稿和审批等回归通过。
- 截图：`docs/research/acceptance/personal-usage-2026-09-26/personal-activity-{320,390,1280}.png`。UI 使用可控 API fixture，后端行为另由真实隔离 HTTP 测试验证，不把 fixture 当生产数据验收。
- 本地验收没有真实模型调用、邮件发送、日历修改或 AWS 资源创建。未涉及额度重置。

## 停止前复评

| 目标 | 本轮改善 | 仍需补齐 |
| --- | --- | --- |
| Today：真实、连续的今日状态 | 只读同步不再伪造最近活动 | 跨来源变化发现、带来源与有效期的记忆、持续日常使用 |
| Muse：后台活动透明 | 会话排序不因查看而伪装为新进展 | 持久浏览器身份、人工接管、受控连接器真实动作闭环 |
| Grok Bot：可验证的重复流程 | 原试运行、时区、暂停、软预算保留 | 事件触发、跨来源核对、长期任务恢复 |
| 手机体验 | 3 个宽度的旧对话查看/刷新路径通过 | 真机键盘、推送送达、弱网连续使用；旧日期当前仅显示时间的可辨识性仍可改进 |

整体能力与体验尚未达到有证据的竞品对等门槛，续做保持启用。此次只解决活跃时间语义，不扩大为全面只读 API 永不写盘的保证，也不改变共享账号的权限边界。
