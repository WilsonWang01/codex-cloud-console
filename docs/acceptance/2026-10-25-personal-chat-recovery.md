## 复现与修复

第一份尺寸记录显示浏览器、可视窗口和 CSS 高度均为 844px，聊天 396px；多出的 65px 来自“个人资料需要核对”警告。广域测试没有模拟 `/personal-context` GET，通用响应缺少 `issue` 字段，界面按既有校验正确显示核对失败。不是已证实的窗口计算故障。补齐有效接口后，正常聊天为 461px，原 422px 门槛通过；没有改聊天高度、隐藏警告或删除旧记录。

随后显式注入 HTTP 503 和缺字段的 200，仍要求可查看原因、重试、保留输入且不自动发消息；发现重试按钮宽 34px、高 44px，手机点击区域不足。唯一尺寸修复是在已有规则加 `min-width:44px`，不改全局按钮、输入框或提示条高度。

实际隔离后端发现另一处真实流程缺陷：已有草稿页通过同页面链接进入本地编号 `facts-source`，后端找到的同一会话云端编号为 `legacy-facts-thread`。路由只比较云端编号，始终认为外部导航未完成；继续新上下文时后端返回 200、页面已显示新草稿，但地址仍为旧编号，刷新可回到旧会话。失败请求、页面和地址已保存，不把超时直接归因于网络。

修复共用路由的两个匹配点：接受当前已加载会话的本地编号或云端编号，随后统一写回云端编号；补齐本地编号的 effect 依赖。项目归属、未完成导航和异步返回的原有门禁保留，未改后端接口、权限、模型或存储。个人与工作会话都用同一规则，不能只修个人入口。
