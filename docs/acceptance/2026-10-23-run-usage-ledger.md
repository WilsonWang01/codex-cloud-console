## 本轮交付

任务用量从可裁剪的运行明细中独立保存到 `state/run-usage.sqlite`。保留原任务 ID、接口和 JSON 状态，不迁移项目、聊天、附件、凭据或显式模型设置。A02 的任务接收事务、执行持有者/代次和持久排队尚未完成，不能把本轮用量账本称为完整 A02。

- 使用 Node 自带 SQLite，没有新增依赖或 AWS 资源。最低 Node 22.16；EC2 Node 22.22.1 / SQLite 3.46.1 实际通过。
- 在原自动化写入队列内，先持久化终态计量，再裁剪任务明细。按运行 ID 替换快照，已知 Codex 回合唯一；重复通知不会累加第二份用量。
- 保留调用方、自动化、运行、回合、状态、模型和单轮计量，不复制提示词、工具参数或完整事件。
- 缺失、负数或无效计量保留为未知。一次已知计量不会被后续缺失快照抹掉；过期快照不覆盖新记录；归属变化或同一回合绑定不同运行会拒绝整个批次。
- UTC 日预算合并原活动状态和账本中的终态证据；活动任务和未知用量仍阻止配置预算下的新任务。
- `/api/clients/usage` 保持原曲线和明细格式，增加账本起始/同步时间、保留边界、行数和磁盘占用。页面明确提示首次接入前的历史覆盖限制。
- 保留最近 32 个完整 UTC 日及当天的精简记录，按日期清理账本自己的旧计量；原任务、会话与附件保留规则不变。SQLite 日志定期检查点，空闲页渐进回收；占用字段包含数据库、WAL 和共享内存文件。
- 账本损坏时查询报错、新任务拒绝启动，严格健康返回 503；不会把统计默认为零继续执行。

## 写入与恢复边界

SQLite 批次使用事务和 FULL 同步模式。账本先提交、JSON 写入随后失败时，已观察到的用量仍在；原任务由现有重启核对机制处理。测试覆盖“已知用量之后变成待核对且缺少快照”的合并，不伪造任务已经完成。

这里没有跨 SQLite/JSON 的总事务，任务接收和幂等仍由原 JSON 记录负责；下一步 A02.2 继续收拢这个边界。升级前回填只能读取仍存在且在账本窗口内的记录，早已被裁剪的数据无法恢复，不承诺完整历史账单。

增加 `ops/backup-usage-ledger.mjs`，用 SQLite 一致性备份 API，实际打开备份进行完整性检查，目标存在时拒绝覆盖。文件为 0600；数据库文件拒绝符号链接和未知版本，不自动修复损坏文件。部署与恢复方法已写入 [setup](../setup.md)；运行中的 WAL 数据库不能只复制主文件。
