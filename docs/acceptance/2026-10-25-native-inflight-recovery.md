## 缺口与实现

原 `verify:external-client:codex` 在首次 `turn/start` 前设置门禁，证明另一条未领取任务可取消，但不能证明 CLI 已进入响应后的取消和进程中断恢复。本轮复用该脚本、生产后端、独立 Node 客户端和真实 CLI 0.157.1，新增互斥的 `--faults-only`，不另造执行器。

私有 HOME/CODEX_HOME、虚构仓库、单自动化/一小时临时令牌和回环地址保持。模型提供端由本机受控 HTTP 响应代替，不使用真实 GPT 模型或现有登录；返回 `response.created` 后保持连接，不返回完成或用量。确认服务运行中且原生请求连接仍打开，再执行测试，不靠等待固定秒数猜测已开始。

1. 独立客户端请求取消，真实 CLI 关闭原请求；从原生线程读回唯一回合的 `interrupted` 状态。任务为 `canceled`，用量未知，不伪造零。
2. 三次重复取消与同事件重放仍找回原终态；原生中断总数为一，目标线程/回合与读回记录相符。
3. 第二条任务进入受控响应后，只强制结束本轮拥有的独立进程组。新后端读回原事件为 `needs_reconciliation`，重复提交和取消仍保持原 ID 与待核对，不创建新回合。
4. 两条任务的调用方用量都保持未知；两个原生请求均已关闭。只有两个启动尝试，启动超限在拒绝前也会记入证据，不隐藏被防护拦下的重放。
5. 临时令牌撤销后查询被拒绝，临时服务结束。从已取消回合读回的原生记录只有 `userMessage`，没有命令、文件、连接器或协作工具活动；强制终止的第二条任务没有获得原生完成回执，仍保持待核对，不冒充工具动作回执证明。

本项没有更换存储、增加依赖、改变权限/模型默认值、修改用户任务或复制登录凭据。`--live`、`--guards-only`、`--faults-only` 互斥，故障模式无法切换为真实模型推理。

## Review 与退出条件

执行者自查，无独立 review agent。核对两个模式共用的登录防护、启动次数硬门禁、未知计量、进程组归属、同事件恢复、令牌撤销与配置并行保护；原材料/文件链路重新运行，不以新故障模式替代它。

CI 增加独立故障模式步骤，保留原有完整回归、个人记忆模拟、真实模式拒绝及运行包检查。该步骤不需要原生工具写产物，不能证明或掩盖 GitHub 主机尚未通过的沙箱产物写入。候选及主线检查以 PR 回执为准，失败会保留并定位，不关闭隔离或提高主机权限。

本轮只证明真实 CLI 配合受控响应时的故障路径，不是生产独立客户端闭环、真实模型推理中取消、公网 TLS、图片交付或外部回调验收。专用生产验收配置、EC2 限时 CPU 对照、个人固定场景、真机与七天观察仍待推进，M2-M5 与整体 goal 保持 active。
