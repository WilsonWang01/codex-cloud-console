# 个人事项失效草稿恢复（2026-10-03）

## 对标与范围

复核 [Muse 安全设计](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)、[Today 产品说明](https://today.ai/articles/blog/what-is-today) 和 [Grok Bot Skills 与 Routines](https://docs.x.ai/grok-bot/skills-routines-and-automations)。这些官方资料强调持续任务、可恢复状态与动作前控制，但未对三款竞品登录后做同一任务的实测，不能据此声称功能对等。

继上一轮事项草稿的同标签刷新恢复后，本轮处理原草稿已被删除的情况。过去本地仍保留其待关联 ID，用户每次点击“重试关联”都会收到 404，无法从该事项继续起草。本轮在服务端明确返回“个人对话不存在”、且这是恢复的旧关联而当前会话列表也找不到该对话时，清除本标签的失效记录并提示再次起草。刚创建草稿后的首次关联若暂时返回相同错误，仍保留 ID 供重试，避免重复建会话。

## 验收与审查

- Playwright 模拟旧关联对应会话已不存在：刷新后重试不会创建会话；收到明确 404 后移除旧 ID，下一次“起草”创建并关联一个新草稿。
- Playwright 模拟新草稿首次关联暂时返回 404：保留 ID，再次“重试关联”沿用同一草稿，不重复创建。
- `npm run verify:local`、构建和 `CODEX_CLOUD_SAFETY_UI_URL=http://127.0.0.1:18787/ npm run verify:personal:ui` 通过；UI 套件同时覆盖 7 个宽度和移动触控检查。
- 只读查看实际代理的个人今日页：云端在线，4 个个人会话与一项 TinyFish 外部操作待核对仍在；390px 与桌面视口布局可读。没有在真实服务中创建事项、会话或执行模型，也没有处理待核对的第三方动作。
- 代码审查：仅修改个人事项的前端恢复分支和模拟测试；不更改后端数据格式、已有任务或第三方数据。

## 限制与发布状态

- 旧关联的缺失由当前会话列表和服务端明确 404 共同判定；若列表仍包含失效会话，旧 ID 不会自动清除，用户可刷新后重试。跨设备事务性创建/关联尚未实现。
- 竞品级事前连接器授权、真实账号任务成功率和跨设备持续任务没有对等证据。
- 本轮仅本地验证与提交，未推送 GitHub 或部署 EC2。发布前仍须取得对应授权，并检查运行任务、备份及校验、严格健康检查与失败回退。
