# 回调配置特殊文件的启动保护

## 范围与复现

日期：2026-10-31，Asia/Shanghai。基线 `f1c5944`，分支 `codex/callback-config-nonblocking-20261031`。继续原 M3/A04 的代码审查，不新增执行引擎、回调目标或接入权限。

`readCallbackTargets` 会在后端监听之前读取操作者指定的配置文件，打开后才核对是否为私有普通文件。原打开方式如果遇到没有写入方的命名管道（FIFO，一种进程间通信文件），会一直等待读取，无法进入文件类型校验。即使配置路径或权限误设，也应明确失败而不是无限等待。此问题属于特殊配置下的启动可靠性缺口，不是已证实的生产故障。

复现使用测试自有临时目录，创建权限为 0600 的 FIFO；独立 Node 子进程调用真实读取函数。旧代码 3 秒后仍未返回，检查报 `ETIMEDOUT / SIGTERM`；原始失败日志保留，没有向管道补写数据来掩盖等待。
