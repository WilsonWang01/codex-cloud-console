# 个人事项草稿的服务端恢复（2026-10-03）

## 对标与改动

再次核对 [Muse 安全设计](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)、[Today 产品说明](https://today.ai/articles/blog/what-is-today) 和 [Grok Bot Skills 与 Routines](https://docs.x.ai/grok-bot/skills-routines-and-automations)。本轮选择持续任务的恢复体验：过去事项起草依赖三个浏览器请求，刷新恢复仍限定同一标签页，无法覆盖换设备或服务器回写中断。

新增 `POST /api/personal/commitments/:id/draft`，串行核对事项并先持久保存会话 ID 的预留，再保存草稿及关联。若草稿已创建但最终关联写入失败，重启后可按预留 ID 继续；已关联的重复请求直接返回同一会话。草稿保存在原聊天状态文件中，不启动模型。客户端取消原有创建、保存、关联的三步组合，只调用这一入口；旧 `sessionStorage` 记录仅用于迁移，存在的个人草稿复用，失效的候选按当前事项创建新草稿。

## 验收与 Review

- 持久化故障注入：最终关联文件替换失败后，预留记录仍在；重新创建 store 并发重试三次只创建一个草稿。首次预留落盘失败时不创建会话。
- 真实隔离 HTTP 后端：三个并发请求返回同一会话，手动修改草稿后停止并重启服务，旧版本请求重放仍保留该内容；会话没有模型线程或模型消息。
- 旧浏览器关联迁移保留已编辑的草稿；工作空间候选不会作为个人草稿复用；完成事项拒绝再次起草，已删除会话的旧版本请求拒绝，新版本请求可创建替代草稿。
- Playwright 模拟接口响应丢失后刷新恢复，并在独立标签页继续原草稿；失效旧关联与有效旧草稿迁移通过。个人 UI 套件覆盖 7 个视口和移动触控尺寸。
- `npm run verify:local`、`npm run verify:personal:ui`、构建及 diff 检查通过。前端事项分包减少约 0.3 KB，后端新增代码限定在原事项 store 与路由，没有新增服务、数据库或依赖。
- Review 修复了返回已有会话时不能把聊天消息固定为空的问题；新入口读取原消息。该流程沿用个人空间的原权限配置。

## 客观限制

这是单控制台进程内串行、跨两份 JSON 文件的可恢复操作，不是多实例数据库事务。已完成关联可跨设备读取；预留记录用于服务重启后的恢复。服务器数据丢失、多实例同时修改同一目录以及底层存储故障不在该保证内。

本轮未执行竞品真实任务，不能据此声称与竞品全面对等。事前连接器动作授权、跨来源主动简报、真实设备通知送达和连续日常试用仍需补齐。
