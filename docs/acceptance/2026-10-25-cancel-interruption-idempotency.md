# 运行中取消去重与停止回执

日期：2026-10-25，Asia/Shanghai。基线 `75a5efd`，工作分支 `codex/cancel-interrupt-once`。本项修复 F04/M2 的运行中重复取消，不新建执行引擎或存储。最终提交、GitHub 检查和合并状态以该分支 PR 的准确头提交为准；本机正式服务与 EC2 仍为 `70b191f`，没有部署或重启。

## 复现

真实隔离 Express 后端连接私有模拟 CLI，控制启动回执和真正停止通知的到达时机。旧实现中，一次取消及三次重试会发送四条 `turn/interrupt`（原生中断命令），检查以 `4 !== 1` 失败。日志 `/tmp/codex-cancel-once-red-20261025.log`。没有对用户任务发送取消请求。

根因是“已经请求取消”和“已经发送中断命令”混用：接口重试、启动回执后检查、超时及网页停止分别发命令；网页入口还可能在本次回合编号未返回时提交空编号。得到中断请求的回应也不表示模型已经停止。

## 最小实现

共享一个按运行回合保存的中断 Promise（异步结果），所有现有中断调用复用它。没有真实线程/回合编号时不缓存，保留取消意图；真实启动回执到达后才发送。脱离原线程的 Review 使用实际 Review 线程，不打断原线程。

结果不明的失败同样保留，不因重试盲目重发。接口取消只登记一次请求事件；网页停止在等待真实终止时返回 `202/pending:true`，真正完成才返回 `200/pending:false`。前端仍等待流的完成通知，不把请求受理当成任务完成。

没有更换数据库、加依赖、改模型默认值、扩大权限或改旧数据。网页停止仍使用既有内存运行意图，不在本项额外引入一套持久取消流程；本项不承诺进程重启后的全局恰好一次发送。
