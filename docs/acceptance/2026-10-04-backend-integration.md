# 2026-10-04 后端集成验收与 Review

## 结论

本轮完善“提交业务事件 → 独立运行 → 读取进度及结果 → 中断或恢复查询”链路。不引入新任务框架、数据库、依赖或权限体系；沿用现有自动化、调用方令牌、幂等及运行记录。没有迁移或清理数据。

## Review 发现与修复

| 优先级 | 问题 | 修复与证据 |
| --- | --- | --- |
| P1 | 独立调用方 Webhook 可传已有 `sessionId`，绕过 Heartbeat 归属验证 | Webhook 拒绝会话参数；Heartbeat 保留调用方/自动化/线程/工作树归属检查，跨调用方 HTTP 测试通过 |
| P1 | 模型、thinking、搜索字段参与幂等摘要，但实际执行没有应用 | 将字段传入既有执行器；HTTP 回归检查持久化模型以及真实 `thread/start` 协议中的 model、effort、web_search |
| P1 | 客户端只给每次 fetch 限时，首次提交、重试及睡眠可超出等待预算 | 总期限覆盖请求、响应正文、重试、轮询与回调；挂起响应和长 Retry-After 故障测试通过 |
| P1 | 默认跟随重定向，令牌可能转发到错误服务 | 只接受 HTTPS 远端 origin，禁用重定向；307 测试验证目标服务收到零次请求 |
| P2 | 临时错误导致服务放弃已接受任务或用新事件重复提交 | 网络和 429/502/503/504 有限重试，复用正文及事件键；超时/中断返回恢复 ID，不自动取消 |
| P2 | 错误类型、未知字段或错误结果被忽略/当作终态 | 独立请求严格校验字段和类型；校验结果 automationId、runId、状态及游标，非 JSON 或错误成功响应不当作完成 |
| P2 | 参考客户端无法传业务输入、续跑或消费同状态下的进度变化 | 支持 `input`、Heartbeat、事件游标、异步 `onProgress`；回调失败保留 ID，回调挂起仍受总期限限制 |

执行权限字段 `sandbox/approval` 明确拒绝，不能通过外部参数改变权限。未知模型的账号可用性仍由 Codex 决定；没有伪造模型可用证明。

## 验收证据

- `npm run verify:external-client`：15 项通过。覆盖提交响应丢失、稳定键与正文、暂时网关错误、重试上限、HTTP 日期 Retry-After、首请求及响应正文挂起、主动中止、超时不取消、进度缺口、异步回调失败/挂起、响应归属异常、重定向及无效参数。
- `npm run verify:regressions`：9 组通过。使用真实 Express HTTP 服务、临时 Git 工作树和模拟 Codex 子进程，验证输入拒绝、执行协议、归属、幂等重放/冲突、撤销、限流以及控制台重启恢复不重复外部动作；参考客户端直接读取这一 HTTP 服务的已完成结果。
- `npm run verify:local`：协议 schema、归一化、构建和全部本地回归通过，包括令牌、审批、预算、个人空间、GitHub 工作流及安装器健康/回退保护。
- `git diff --check` 通过。没有前端交互变更，本轮不声称重新完成手机/桌面 UI 或实际付费模型验收；构建仍有既有主包超过 500 kB 的提示，不在本轮引入无关拆包改动。

所有测试使用假服务端或隔离的临时状态/模拟 Codex，没有运行付费模型、发送邮件、修改日历或触发远端 GitHub 写入。

## 架构与剩余边界

参数校验放在既有 `external-automation.mjs`；路由只接入校验并传递参数，没有把新逻辑继续堆入主服务。参考客户端是可导入的小型单文件模块，使用 Node.js 内置 fetch、AbortSignal 和 timers，不创建持久连接管理器、队列服务或泛化 SDK 层。

接口仍是异步任务 API，不是 OpenAI 兼容聊天接口。完成通知推送、隔离文件下载、外部编排及不可信多租户 worker 尚未实现。工作执行器共享系统用户和 Codex 账号，隔离工作树不是安全沙箱。幂等窗口默认 24 小时，超出窗口的未知任务须人工核对；客户端/回调中止无法撤销服务器任务或已开始的外部操作。
