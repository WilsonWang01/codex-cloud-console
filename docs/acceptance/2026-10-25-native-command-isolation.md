# M2 原生命令隔离验收前置

状态：新增可重复的原生 CLI 检查，不是新的生产执行权限策略，也不代表 API 客户端业务闭环已完成。正式本机与 EC2 仍为 `fb45f15`，没有更新后端、创建调用方令牌或重启服务。

## 为什么先做

现有独立令牌限制自动化/运行归属，工作树隔离代码目录，但执行默认仍是全权限。不能把这两者说成操作系统安全沙箱。生产独立客户端的 JSON/材料/文件交付与取消还缺真实证据，新增专用测试仓库、按需自动化及一小时令牌已申请具体确认，未收到答复前不创建。

本轮先核对真实 CLI 是否能执行需要的限制，避免只改提示词或配置文字就声称安全。没有额外创建 AWS 资源、扩大现有账号权限或修改业务日历/邮箱。

## 可重复运行

在包含本轮脚本的代码版本中，使用已经安装的 Codex CLI：

```sh
npm run verify:command-isolation:codex
# 使用已安装的其他路径时明确指定，不自动升级或安装 CLI：
CODEX_SCHEMA_CLI_BINARY=/path/to/codex npm run verify:command-isolation:codex
```

默认查找本机已缓存的 `@openai/codex@0.157.1`，没有时直接失败，不自动安装。脚本创建全新的临时 HOME/CODEX_HOME，认证存储只使用该临时目录文件，不读取现有登录；模型服务固定为 127.0.0.1 的模拟接口并核对原生返回的 provider。模拟用量不写入生产账本、不当作真实模型消耗。

## Review 与失败记录

- CLI 0.157.1 实际使用 `additional_tools` 的命名空间和原生 `custom_tool_call`。调试时把它误当作直接的 exec_command 函数，模拟接口返回非重试 400；已按实际契约修正，没有运行真实推理。
- 首次 EC2 的四项限制检查通过，但后台插件同步在写临时目录，清理报 ENOTEMPTY，因此整轮记为失败。测试进程启动时关闭插件/远程插件同步，并对自己创建的临时目录采用标准库有界清理重试；成功只在清理后输出。失败残留的明确测试目录已清理，未触碰业务数据。
- 增加原生命令完成回执证明后的 EC2 复测，捕捉到 MCP 目录先返回 starting 的竞态。现在只在已观测的 starting/notStarted 下限时查询同一线程；连接失败、未知状态不重新建进程或运行模型。第一次派发脚本另有字符串编码错误，在启动单元前失败；确认单元不存在后才修正，不因观测超时盲目重启。
- CLI 查找在创建临时目录前完成，避免缺少 CLI 时留下临时目录。测试不给任何原生额外权限请求自动批准。

## 仍不成立的结论

这只证明明确参数下的命令写入/联网与虚构 MCP 禁用，不证明整个宿主文件读取隔离、所有插件/浏览器策略或不可信多租户安全。模型和认证连接本身不在命令网络限制内。

即使这次传入 `features.multi_agent=false`，实际工具目录仍出现协作/后续任务入口，输出如实保留 `delegationToolsAdvertised:true`；本轮没有调用它们，**不能宣称额外模型调用已经被禁止**，原因尚未定位。

脚本没有接入当前生产执行器；现有 API 仍只能向受信任调用方开放。真实令牌链路、模型材料理解、结构化结果和文件下载/恢复/取消、MCP 用户客户端、回调、真机、七天观察和用户评价仍需完成，M2-M5 与原生 goal 不提前结束。
