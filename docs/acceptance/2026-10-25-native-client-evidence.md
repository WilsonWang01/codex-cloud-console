## 已验证链路

新增 `npm run verify:external-client:codex`：真实 CLI 0.157.1、临时回环控制台、独立虚构 Git 仓库与受限工作树，复用生产后端、队列、JSON 校验、私有结果、原生计量和两个参考客户端，没有另造执行器或增加依赖。

- 独立 Node 子进程从本机文件提交 Markdown/PDF 和 JSON schema；随机编号及两份材料中的数值不写入任务提示，不能靠复述提示通过。
- 工作树内生成报告，最终 JSON、报告内容和 SHA-256 均核对。报告交付后只改本轮生成的原文件，重启控制台，再由独立 Python 子进程下载；仍得到原私有副本且校验通过。
- 人工释放的测试门禁只暂缓本轮首个原生 `turn/start`，用于检查另一个未领取任务取消、用量为零；不声称已验证真实推理中的取消或服务中途重启。
- 同一事件键和相同输入在服务重启后找回原运行；下载、重放和取消没有新增原生回合。调用方账本与原生回合用量一致；单自动化临时令牌一小时到期，完成后撤销并验证不能下载。
- 最终脚本从原生线程读回实际工具类型，未知工具活动拒绝通过；关闭本轮服务进程组，私有证据保留在输出所示临时目录，不上传登录、令牌、原生完整记录或用户内容。

默认完整模式使用无凭据临时 HOME/CODEX_HOME 与固定回环模拟模型。真实 CLI 通过原生文件补丁工具写入产物，模拟 token 不写生产账本，不计作真实模型成功。完整模式在本机与现有 EC2 的隔离服务通过；GitHub CI 仅运行显式 `--guards-only` 的三个真实模式入口拒绝检查，没有启动原生 CLI 或模型，不证明原生文件链路、沙箱命令或生产闭环。原有全量回归、模拟个人质量和运行包门禁保持。

## 发现的配置副作用

真实链路成功不等于整体验收安全通过：独立核对发现 CLI 自动在本机共享 `~/.codex/config.toml` 为本轮虚构仓库新增 `trust_level = "trusted"`。只去掉这一段即可逐字节匹配测试前 SHA-256，代理 LaunchAgent 原字节保持；没有把未知修改简单归为其他用户操作，也没有恢复整份旧配置覆盖并行修改。原始汇总中的 `productionConfigWrites: 0` 不能证明共享 CLI 配置未变化，该字段已改为限定范围的 `productionConsoleWrites`。

在无凭据临时目录复现同一自动登记行为；过程级信任覆盖也未阻止写入，因此没有把该尝试当解决方案。新增防护：`--live` 除额度批准外还必须显式提供私有、已登录、不同于正常 Codex 目录的 `CODEX_EXTERNAL_LIVE_HOME`，使用共享目录会在启动 CLI 和调用模型前拒绝，脚本不复制认证或代办登录。普通 HOME 和 Git 全局配置也隔离，关闭本轮仓库 Git hooks。结束检查 CLI 配置不变，或差异仅为本轮测试信任项；其他变化失败保留，不自动覆盖。

这项独立登录目录模式已完成本机拒绝路径与真实 CLI 模拟验证，最终 CI 另看回执；未再次运行真实模型，不能把首次共享目录模型结果写成最终专用登录目录实测。CLI 在专用目录仍会留下本轮信任项和原生测试线程，不承诺无状态。首次共享目录的信任项已申请用户确认后再窄范围清理，当前不擅自删除；这不涉及线上权限或服务。
