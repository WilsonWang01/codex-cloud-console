# F01 当日日用量裁剪保护

日期：2026-10-22。关联：[下一阶段开发方案](../development-plan-2026-10-22.md) M1/F01、[活动 goal](../goals/codex-cloud-reliable-agent-v1.md)。

## 结论与范围

本地修复和相关回归通过。当天参与日预算计算的 app-server 运行不再受普通 200 条历史上限裁剪；未知用量仍阻止配置了预算的后续运行。此项不改变预算大小、UTC 日口径、已有任务与模型配置，不迁移数据库，不删除生产数据。

修复已推送 GitHub main，完整本地验收与 GitHub CI 通过，尚未部署 EC2。无真实模型调用、AWS 资源变更或第三方写入；未通过此次测试证明所有线上任务及页面均正常。

## 复现和实现

先新增回归，再修改代码。旧实现的 8 项预算测试中 4 项失败：250 条当日运行仅保留 200 条；最老的未知用量记录丢失；当日边界记录被裁掉；新进程重读持久文件后，240,000 token 门槛错误允许继续运行。

修复复用 `server/run-budget.mjs` 的 `dailyTokenBudgetRuns`，预算与裁剪共用同一选择规则：runner 为 app-server，开始时间在当前 UTC 日零点至检查时刻之间。保留策略使用原始对象集合，不修改输入记录，不增加第二套预算逻辑。

当日保护不占普通历史的 200 条额度；进入下一 UTC 日后，仍按原来的普通历史、活动任务、幂等窗口、恢复窗口和调用方最近会话规则保留。没有新增永久保留全部历史的规则。

## Review 与遗留限制

- 改动只涉及两个现有后端模块和预算测试，无新增依赖、路由或权限。
- 保留当天记录不以预算当前是否启用为条件，避免当天稍后启用预算时已经丢失计量证据。
- 原来已被裁掉的运行无法凭空恢复；此次修复只保护后续仍在存储中的记录，不回填或伪造历史用量。
- 当日高频运行会保留更多明细，磁盘和扫描成本随当日任务量增长；长期解法仍是 A02 独立用量账本，而非进一步提高固定历史数字。
- 日预算仍是软门槛，不能限制已接受的单次模型运行实际消耗；本项不改变跨日运行按开始日期归属的既有规则，不代表财务硬止损。
- 仅当前检查时刻以前的记录参加预算，未来时间戳及缺少有效开始时间的记录保持旧预算语义；时钟漂移/异常数据治理不在本项中偷偷改变。
- 当前工作区同时有本型转接变更；只提交本方案和 F01，不包含 README、package.json、server/index.mjs 及本型脚本的并行修改。
