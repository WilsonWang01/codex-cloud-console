# 当前 CLI 的 API 取消与重启恢复

日期：2026-10-30，Asia/Shanghai。

## 缺口与最小修正

生产 CLI 已为 0.165.0，但原生独立客户端验收脚本仍把版本固定为 0.157.1。实际指定 `CODEX_SCHEMA_CLI_BINARY` 和已有的 `CODEX_SCHEMA_CLI_VERSION=0.165.0` 后，脚本在创建测试目录前被旧版本断言拒绝，无法验证当前 CLI 的中断和恢复。

只修改这一份脚本：复用现有版本环境变量，默认仍为 0.157.1；显式版本必须是固定稳定版本，且真实程序的 `--version` 必须完全匹配。不接受 `latest`、不默默换程序、不修改生成的协议、其他测试或生产配置。

CI 保留旧版故障检查，另外固定 0.165.0 执行原生运行中取消/重启恢复，以及 Linux 实际命令边界检查。新步骤的精确结果以本文件对应 PR 的同一头提交检查为准，未通过不能合并；不能拿本机结果代替 Linux，也不能拿只列工具目录的检查代替执行边界。

## 已有本机证据

| 检查 | 结果与范围 |
| --- | --- |
| 0.165.0 运行中取消 | 真 CLI 请求进入本机受控响应后，取消关闭响应；原生回读为 `interrupted`，API 为 `canceled` |
| 重复取消与同键提交 | 不再启动回合，只产生一次原生中断 |
| 进程强制结束 | 只结束本轮独立测试进程组；原事件重启后保持同一任务，为 `needs_reconciliation`，不自动重放 |
| 未完整结束的用量 | 两种中断都保持未知，不编造零用量或成功 |
| 回合数量 | 每版本只有两个合成回合、两个本机响应请求、一次中断；没有实际模型服务请求 |
| 旧版兼容 | 0.157.1 执行相同故障检查通过，没有删旧门禁 |
| 版本拒绝 | 不固定版本、实际程序版本不符、未显式选择却提供新版程序，三种情况均在创建测试目录前拒绝 |
| 客户端回归 | 29 项 Node/Python 客户端检查通过；三个付费/独立登录目录入口保护通过 |

官方 App Server 文档区分取消请求的空对象回执与最终 `interrupted` 状态；本项同时检查 API 终态、原生回合和受控响应关闭，没有把“已发取消”当作“已停止”。协议依据：[OpenAI 官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)。

测试使用独立无登录目录、虚构项目和只监听 `127.0.0.1` 的合成响应服务。测试服务与 CLI 进程不携带正式令牌，只使用本轮私有目录；仅本轮进程组参与故障注入。共享 CLI 配置在两版本检查前后哈希一致，所有测试进程及本机监听结束，证据保留在私有目录。

## Review 与退出边界

- 保留显式模型 `gpt-6-sol / medium`、受限工作区、禁用连接器/联网/委派、独立进程和原事件去重断言；版本选择不放松这些检查。
- 变更仅为验收工具和 CI，不改 API 运行时代码、权限、模型默认值或前端；不需要发布或重启线上控制台，也不为没有页面变化的测试改动补造截图。
- 真实模型、生产令牌创建、EC2 CPU 专项检查、第三方写入与额度重置均为 0。一次性测试 HOME 内允许 CLI 登记虚构仓库信任项，不是生产共享配置变化；上一轮生产测试信任项的清理仍待单独确认。
- [生产材料交付样例](2026-10-30-production-api-client.md)已经证明真实模型图片输入、JSON/报告、下载、同键找回和计量；本项补当前 CLI 的受控故障，不把合成响应当作真实模型中断费用或上游停止时延的证明。
- Linux 命令检查使用临时内外文件和本机回环探针，禁止通过放宽沙箱、跳过失败或增加权限来让检查变绿。它不等于同一台 EC2 上已完成全部安全检查，更不提供不受信任多租户隔离。

M2 退出仍须结合生产样例、原有持久任务/用量及本项准确 Linux 结果逐项复评。M3 回调/MCP 现场接入、个人固定场景、真机、七天观察及真实评价继续保留，完整 goal 不提前完成。
