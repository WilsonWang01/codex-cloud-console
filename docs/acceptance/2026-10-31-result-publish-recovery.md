## 缺口与方法

现有检查覆盖了写副本途中执行权失效，以及任务完成后的正常重启；尚未直接证明“副本已经可靠保存、任务或用量还未提交”这两个准确窗口。本轮复用真实控制台、SQLite、私有结果、外部 Node 客户端和原 Codex 协议替身，在现有 HTTP 集成中增加一个双阶段用例。

测试专用 `--import` 文件只在本轮临时控制台进程挂接 SQLite 语句：匹配本轮虚构提示词和运行 ID，在目标语句执行前暂停；不添加产品环境开关。父进程通过独立只读连接检查已提交的数据，再对自有进程发送真实 `SIGKILL`。重启不加载挂接文件，不修改数据库、配置或系统时间来伪造恢复。

## 实际定向结果

| 故障窗口 | 中断前的实际证据 | 原进程退出后的实际恢复 |
| --- | --- | --- |
| 副本提交后、任务终态写入前 | 任务仍 running，结果 ready；报告及清单两份文件完整指纹匹配；用量表 0 行 | 原任务变为 needs_reconciliation，原键不重放、用量保持未知、下载 409。不把保存了文件等同整项任务成功；原副本和容量记录保持，模拟过期清理也不删除待核对数据 |
| 任务终态提交后、用量事务提交前 | 任务已 completed，结果 ready，两份副本完整；用量表仍 0 行 | 原任务保持 completed，真实接口补记原任务一条用量、130 个合成 tokens；JSON 校验和私有报告下载通过，重复读取不重复计量 |

两个阶段均核对同一任务 ID、原事件键、调用方、原线程/回合、结果清单及所有副本；原工作树报告在测试进程停止后被改写，下载仍取得原私有副本。每阶段只有一个后端 `turn/start`，两次同键找回没有再执行。130 是协议替身的测试计数，不是真实模型费用；没有运行真实 CLI、模型、连接器或业务动作。

未知状态的过期检查仅向独立测试存储传入未来时间，不调整本机时钟，不计作七天真实观察。它验证结果已 ready 时仍受“待核对不自动清理”保护，不以恢复成功为由擅自结案。
