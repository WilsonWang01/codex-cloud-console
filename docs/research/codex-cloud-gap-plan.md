# Codex Cloud Console Gap Plan

本文件记录把当前云端 Codex CLI 控制台继续对齐 Codex App 的调研结论和落地方案。目标不是简单复制一个终端网页，而是把本项目升级成一个稳定的云端 Codex app-server 薄客户端：浏览器负责交互，云端负责持久 session、thread/turn 协议、自动化任务、上下文和权限状态。

## 目标

- 对齐 Codex App 的核心交互：项目、thread、turn、slash command、goal、token usage、主动/自动压缩、模型/推理深度、MCP、插件、文件上传、图片输入、权限状态。
- 保持云端常驻稳定：浏览器断开不影响正在运行的 turn，重连后可恢复状态和事件。
- 支持自动化任务：定时、手动、webhook/heartbeat 触发，任务运行有独立状态、日志、thread、diff 和结果摘要。
- 明确只借鉴外部项目的可迁移设计，不盲目 clone 大量代码；涉及 AGPL/GPL 项目时只借产品和架构，不复制实现。

## 当前判断

当前项目已经能通过 Web UI 调用云端 Codex app-server，并支持模型、推理深度、上传、goal、compact、token 展示等一部分能力。但整体仍像“自定义聊天应用 + 局部 app-server 调用”。

后续关键不是再补几个按钮，而是让 app-server 成为唯一事实源：

- thread 列表、历史、改名、归档、分叉来自 app-server。
- turn 运行、steer、interrupt、compact 都由 app-server 生命周期驱动。
- token usage、goal、MCP、plugin、permission、diff、approval、tool call 都按 app-server item/event 渲染。
- 本地 JSON store 只保存 UI 偏好和缓存，不保存消息事实。

## 方案

### P0：协议层和会话事实源

1. 用当前云端 `codex app-server generate-ts` 生成 TypeScript schema，放到 `src/generated/` 或 `server/generated/`。
2. 新建后端 `CodexAppServerClient`：
   - 维护长期 app-server 进程或 socket。
   - 封装 request/response id、timeout、重试、初始化握手。
   - 统一处理 app-server notifications，并广播给浏览器。
   - 支持 app-server 崩溃后的自动重启和 thread resume。
3. 直接映射官方方法：
   - `thread/list`
   - `thread/read`
   - `thread/start`
   - `thread/resume`
   - `thread/fork`
   - `thread/archive`
   - `thread/name/set`
   - `thread/turns/list`
   - `thread/compact/start`
   - `turn/start`
   - `turn/steer`
   - `turn/interrupt`
   - `model/list`
   - `mcpServerStatus/list`
   - `plugin/list`
   - `permissionProfile/list`
4. `chat-sessions.json` 退化为 UI metadata：
   - active thread id per repo/cwd
   - 用户自定义标题缓存
   - UI 过滤/排序偏好
   - 最近附件草稿
5. 修复会话跨项目：
   - 每个 thread 必须绑定 `repoId + cwd + appServerThreadId`。
   - 前端切换项目时，只展示同一 cwd 下的 threads。
   - 如果 app-server 返回 thread 没有 cwd metadata，则通过第一次 `thread/start/resume` 时写入本项目 metadata。

### P1：Codex App 风格 UI 和 slash command

1. 主布局保持简洁：
   - 左侧：项目和 threads。
   - 主区：chat timeline。
   - 底部：composer。
   - 右侧：默认隐藏，可作为 status/diff/log drawer。
2. 把模型、推理深度、goal、compact、auto-compact、capabilities、sessions 等配置收进 `/` 命令菜单。
3. 支持命令：
   - `/status`：thread id、cwd、token usage、limit、权限、MCP、插件、云端连接。
   - `/goal`：查看、设置、清除 goal。
   - `/compact`：主动压缩当前 thread。
   - `/model`：切换模型。
   - `/reasoning`：切换低/中/高/超高。
   - `/permissions`：查看或切换 permission profile。
   - `/mcp`：查看 MCP server 状态。
   - `/review`：进入 review 模式。
   - `/new`：新建 thread。
   - `/fork`：从当前 thread 分叉。
   - `/archive`：归档当前 thread。
4. `$` 唤起 skills 或 agent presets；`@` 可后续用于文件或项目引用。
5. 命令菜单需要支持键盘：
   - 输入 `/` 打开。
   - 上下键选择。
   - Enter 执行。
   - Esc 关闭。
   - 子命令用二级 palette，不堆复杂面板。

### P1：消息渲染升级为 item timeline

1. 不再把所有事件拼成纯文本。
2. 根据 app-server item/event 类型渲染：
   - user message
   - assistant message
   - reasoning summary
   - command execution
   - file edit
   - diff
   - approval request/result
   - MCP tool call
   - plugin/app call
   - token usage update
   - compact event
   - error/event warning
3. 工具调用默认折叠，失败、approval、长命令突出展示。
4. 参考 The Companion 的多视图：
   - Chat：主对话。
   - Diff：当前 turn 文件变更。
   - Process：正在运行的命令和后台任务。
   - Terminal：保留完整 CLI session 入口，但不作为默认交互。

### P1：上下文压缩和 token usage

1. 主动压缩走 `thread/compact/start`，展示完整状态：
   - connecting
   - resuming thread
   - compacting
   - summary generated
   - token usage updated
   - done / failed / cancelled
2. 压缩时在 timeline 中插入一个 Codex 状态泡泡，并在 `/status` 中同步显示。
3. 浏览器断开不能让压缩卡死：
   - 后端保存 compact job 状态。
   - 前端重连后根据 thread id 恢复 compact 状态。
   - 超时或 app-server 退出时明确标记 failed。
4. token 展示只信 app-server：
   - `thread/tokenUsage/updated`
   - `turn/completed.tokenUsage`
5. UI 展示分开：
   - 当前上下文：`last.totalTokens / modelContextWindow`
   - 累计 token：`total.totalTokens`
   - 自动压缩阈值：配置值和 scope

### P2：云端稳定性和连接模型

1. 改成 server-owned process：
   - 浏览器发起 turn 后，turn 属于服务器，不属于浏览器连接。
   - 浏览器刷新或断开时，后端继续接收 app-server 事件。
   - 浏览器重连后读取 thread timeline 和最近 event buffer。
2. 增加 event broker：
   - WebSocket 或 SSE 统一出口。
   - 支持 heartbeat。
   - 支持 last-event-id 或按 thread 重放最近 N 条事件。
   - 区分 app-server event、console event、automation event、infra event。
3. 分层健康状态：
   - local proxy：本地 127.0.0.1 入口是否可达。
   - EC2 console：`/healthz`。
   - app-server host：是否在线、版本、最近重启时间。
   - OpenAI auth：`codex login status`。
   - repo health：cwd 是否存在、git 是否可读。
4. 前端“连接断开”文案要精确：
   - 本地代理断开。
   - EC2 服务断开。
   - app-server 断开。
   - OpenAI 登录失效。
   - 当前网络公网入口 reset。
5. systemd 设计：
   - `codex-cloud-console.service`：Web/API。
   - `codex-app-server-host.service`：长期 app-server host。
   - 可选 `codex-cloud-agent.service`：自动化 runner。
6. HTTPS 入口：
   - 优先 Tailscale Serve 或 Cloudflare Tunnel。
   - Caddy 作为普通 HTTPS fallback。
   - 公网 8787 只作临时 fallback，必须有安全组限制或应用层 token。

### P3：自动化任务层

1. 定义统一 `Automation`：
   - id
   - name
   - repoId/cwd
   - trigger：manual / schedule / webhook / heartbeat
   - prompt
   - model/reasoning/permission
   - worktree policy
   - status
   - last run / next run
2. 每次运行生成 `AutomationRun`：
   - runId
   - threadId
   - repo/worktree
   - startedAt/finishedAt
   - status
   - event log
   - diff summary
   - result summary
   - failure reason
3. 两种运行模式：
   - Project automation：每次新建或复用专属 automation thread。
   - Thread heartbeat：绑定现有 thread，像 Codex App heartbeat 一样继续同一上下文。
4. 默认使用 git worktree 隔离：
   - 自动化任务不直接污染主 checkout。
   - 成功后展示 diff 和 merge/apply 按钮。
   - 失败后保留 worktree 供排查。
5. 增加 inbox：
   - Needs attention：失败、需要人工、产生 diff、approval blocked。
   - Active：运行中。
   - Recent：最近完成。
   - Archived：已处理。

### P3：上传、多模态和文件工作流

1. 保留并强化：
   - 粘贴截图。
   - 拖拽文件。
   - 上传图片、PDF、文本、代码文件。
2. 图片：
   - 作为 app-server local image input 传入。
   - 在 timeline 中展示缩略图。
3. 文件：
   - 保存到 repo `.codex-cloud/uploads/YYYY-MM-DD/`。
   - composer 中显示附件 chip。
   - 发送消息时附带路径引用和文件说明。
4. 上传失败需要明确状态，不吞错误。
5. 后续补文件浏览器：
   - repo tree
   - changed files
   - uploaded files
   - open in diff/editor

### P4：权限、安全和审计

1. 云端默认可使用 `danger-full-access + approval never`，但 UI 必须清楚展示。
2. 增加 permission profile：
   - read-only
   - workspace-write
   - danger-full-access
3. 即使全权限，也记录：
   - shell command
   - file edit
   - network/tool call
   - MCP/plugin call
   - automation run diff
4. 外部访问：
   - 长期入口必须有 token、Basic auth、Tailscale 或 Cloudflare Access。
   - 不长期裸开公网 console port。
5. 增加审计页面：
   - 最近命令。
   - 最近文件修改。
   - 自动化运行。
   - app-server 重启和错误。

## 推荐实施顺序

1. P0：协议层长连接、thread list/read/start/resume、事件广播。
2. P0：将会话列表事实源切到 app-server，修复跨项目和新会话丢失。
3. P1：简化 UI，落地 `/` command palette。
4. P1：item timeline 渲染 app-server 事件。
5. P1：修复 compact/token 的状态机和断线恢复。
6. P2：server-owned process、event broker、分层 health。
7. P3：自动化任务 run model、worktree 隔离、inbox。
8. P3/P4：文件/Git UI、通知、安全审计和移动端优化。

## 可接受的剩余 gap

以下 gap 如果底层 Codex CLI/app-server 不提供能力，可以作为明确剩余差异：

- Codex App 私有桌面能力，例如原生窗口、系统级通知、桌面宠物、某些未公开插件 UI。
- app-server 未暴露的内部历史搜索或私有 thread metadata。
- 未公开的 ChatGPT 账户配额详情。
- 某些 OpenAI/Codex 内部云任务能力，如果仅对官方 Codex App 开放。
- 本地 IDE 深度集成能力，除非通过 SSH/VS Code Remote/Tailscale 另接。

## 2026-05-30 落地状态

- P0/P1 已切到官方 app-server 主链路：schema 由 `codex app-server generate-ts` 生成；thread list/read/start/resume、turn/start、steer、interrupt、goal、compact、token usage、model list、MCP、plugin、skills、permissions、fs、command/exec 均优先走 app-server。
- 会话跨项目问题已修复：session 按 `repoId + cwd + appServerThreadId` 过滤和恢复；自动化 run 创建的非活跃 session 不会覆盖当前项目的 active session。
- P1 UI 已改为 Codex App 风格的 session composer：`/` 菜单支持 status、goal、compact、auto-compact、model、reasoning、permissions、MCP/plugins/capabilities、review、fork、archive、新会话和新项目。
- P1 item timeline 已有轻量分类渲染：command、file edit、diff、MCP/tool、reasoning、compact、review、error 会按 app-server item/status 显示标签和专用样式，不再全部混成普通文本。
- P1 历史读取链路已修正：`thread/read` 归一化后的 `messageType/status/turnId` 不再被 `/api/chat/history` 二次归一化丢弃，刷新页面后仍能按 app-server item 类型渲染 timeline。
- P1 结构化 item 详情已接入：command/fileChange/MCP/tool/webSearch/imageGeneration 的关键信息从 app-server item normalizer 传到前端，timeline 中可展开查看命令、cwd、退出码、文件变更和 diff。
- Diff 已接入 `/diff` 指令，直接调用 app-server `gitDiffToRemote` 显示当前仓库相对远端的变更。
- Review 面板已参考 MIT `codexui` 的 `ReviewPane/reviewGit` 和 `parseReviewText` 落地：`/review` 会打开 Codex App 风格 review 面板并启动官方 `review/start`，面板支持 workspace/base branch、unstaged/staged、文件/hunk 级 diff、stage/unstage/revert，以及官方 review 文本中的 finding 解析和按文件定位。每条 finding 现在可编辑评论草稿、复制 `::code-comment` inline comment 指令，或一键发回当前 app-server thread 让 Codex 继续处理。
- `$` / `@` composer 唤起已接入：`$` palette 使用 app-server `skills/list` 的 repo-scoped skill 列表，参考 MIT `codexui` 的 skill grouping 逻辑；选中后后端会把 `$skill` 解析为 app-server `skill` UserInput。`@` palette 使用 app-server `fs/readDirectory` 文件树和项目列表，选中后后端会把 `@path` / `@project:id` 解析为 app-server `mention` UserInput。
- 上下文压缩已走 `thread/compact/start`，前端展示主动压缩状态；token 展示分为当前上下文、累计 token 和自动压缩阈值，数据只信 app-server。
- P2 已完成 server-owned turn/compact：浏览器断开后后端 job 继续接收 app-server 事件，前端可通过 active job/event buffer 重连恢复；`/healthz` 分层检查 EC2 console、app-server、Codex 登录和 repo health。
- MCP OAuth 已接入官方 `mcpServer/oauth/login`，并通过本地 proxy relay 解决 EC2 loopback callback 不能从本地浏览器完成的问题。
- P3 自动化任务已落地真实 app-server run model：每次手动 run 创建 `AutomationRun`，默认使用 detached git worktree，记录 thread/session、event log、summary、diffStat、error，并在 UI 中展示 automation inbox。
- P3 webhook/heartbeat 入口已接入同一个 app-server runner：`POST /api/automations/:id/webhook` 走独立 worktree run，`POST /api/automations/:id/heartbeat` 可传 `sessionId` 绑定已有 app-server thread；生产环境需要 `CODEX_CLOUD_WEBHOOK_TOKEN` 或 `AUTOMATION_WEBHOOK_TOKEN`。
- 自动化页面已补 Webhook/heartbeat 指引面板，会按当前控制台入口生成调用 URL、curl 示例和外部触发配置向导；向导支持 curl、systemd timer、GitHub Actions schedule、Cloudflare Worker scheduled trigger 的可复制配置，不在 UI 暴露真实 token。
- P3 稳定性补丁已接入：console 启动时会把服务重启前遗留的 `queued/running` app-server 自动化 run 标记为 failed/interrupted，并写入 audit，避免 inbox 出现无法恢复的假运行状态。
- 现有 systemd timer 已通过兼容 runner 切到 app-server API：`/home/ubuntu/codex-cloud/bin/run-local-automation` 现在调用 console 的 `/api/automations/:id/run`，旧 `codex exec` 脚本保留为 `.codex-exec.bak`。
- P4 权限和审计已落地：默认 `danger-full-access + approval never`，`/permissions` 可切换只读、工作区写入和完整访问，turn 参数直接映射到 app-server sandbox/approval；app-server shell、file edit、web search、MCP/tool、approval、warning/error、app-server ready/exit、automation trigger 事件会写入 audit store。日志页已按 shell、文件、网络、MCP、权限、自动化和 host 分类筛选，详情区会按事件类型抽取 command/cwd/path/query/server/tool/decision/worktree 等关键字段，并保留原始 detail。运行中的 approval/request-user-input/MCP elicitation 会同步成 job event，前端 timeline 显示 Approval 状态并可展开详情；MCP/tool/webSearch/imageGeneration 也有结构化展开。
- UI 对齐继续推进：左侧新增跨项目“收件箱”入口，聚合 automation needs-attention、running、异常 audit、脏工作区，并支持从卡片直接跳转到对应 app-server thread 或自动化任务。默认对话页右侧运维信息已收敛为轻量“上下文”栏，把待处理入口、项目状态、云端状态和最近日志放在可展开区域，减少 Codex App 会话体验里的仪表盘感。

## 2026-05-31 UI/交互再评估
