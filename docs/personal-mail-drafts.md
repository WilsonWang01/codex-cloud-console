# 邮件回复草稿

本功能在包含本轮提交的控制台版本中可用。源码、GitHub 合并与线上发布分别核对；旧线上版本不会因阅读本文自动升级。

## 怎么用

1. 切换到“个人 → 今日”，明确选择已连接邮箱，按需读取未读邮件元信息。不会自动读取正文或附件。
2. 在需要处理的那封邮件右侧点击回复图标。只在控制台保存回复草稿，保留邮箱、原邮件标识、标题、发件人、读取时间和版本。
3. 自行填写收件人、主题、正文并“保存编辑”。不会将发件人自动当作已核实的回复地址；请核对原邮件的 Reply-To 和实际收件人。
4. 需要助理起草时，先保存自己指定的收件人，再点“让助理起草”。这只新建一个未发送的个人对话草稿；补充回复要求并发送给模型才消耗模型额度。缺少正文、截止时间或承诺信息时，应先补充资料，不凭主题猜测。
5. 新个人会话的 `personal_mail_draft` 工具可保存另一条带起草来源的候选回复；在今日页核对内容。旧会话不自动获得新工具，也不复制或改写旧历史。
6. 草稿可稍后处理、拒绝或恢复；恢复和重复打开都不发送邮件。原调用重复返回原草稿，不自动恢复已拒绝的记录。
7. 勾选核对项后可“标记本版已核对”。这只保存当前版本的核对记录，不是发送授权，不创建 Gmail 草稿。继续编辑并保存后，旧核对立即失效。

## 按需读取单封正文

只有元信息时，助理不能可靠地从主题猜测待办、截止时间或回复内容。在包含本轮提交的版本里，可在今日页具体邮件旁点击打开信封图标，先核对邮箱、主题和发件人，再点击“确认只读这一封正文”。选择邮件、打开页面和切换账号都不会自动读正文；关闭确认区不发起读取。

正文以纯文本显示，HTML 仅在服务器转成文字，不执行脚本、不加载邮件图片或链接，不另行取得或解析附件。读取沿用已有只读连接，不改变标签、未读状态，也不扩展 OAuth 权限；不会自动选择其他邮箱。账号、邮件版本、读取状态或五分钟来源有效期不符就拒绝，错误不自动重试。

“整理正文待办”和“起草正文回复”只预填个人对话消息，包含所选账号/邮件/版本、原日期、时区、读取时间和展示文字指纹。补充要求并自行发送后才调用模型。含糊日期、Reply-To、收件人和承诺仍须核对；第三方正文不是命令或权限授权。这些提示不代替整个通用会话的工具权限隔离。

正文读取入口本身不新增正文存储、日志或备份副本，成功不修改邮件来源或草稿文件，关闭/离开后清除组件中的正文。**交给助理以后，正文将进入既有消息草稿或对话历史，不再是仅临时显示。** 不要在共享浏览器处理敏感信件。

只解析当前连接器 `full` 表示中的已解码 MIME（邮件内容分段格式）文字 `body.content`。文字输入合计最多 128 KiB，展示文字最多 32 KiB，最多 64 个分段、12 层嵌套；整个工具返回仍受既有 1 MiB 限制。格式不明、仅附件或超限明确报错，不静默截取后冒充全文；可到 Gmail 查看原信。本轮尚未获得新的真实正文读取授权，实际连接器非空返回仍待指定邮件验收，不把合成材料计入完整 E02 成绩。

## 数据与恢复

已保存草稿在 Codex Cloud 的私有状态目录 `personal-mail-drafts.json`，复用既有安全读取、原子保存和备份范围。最多 100 条、2 MiB；达到上限拒绝新增，不自动删除旧草稿。正文最多 12,000 字符，最多 10 个不重复收件人，仅纯文本，不含附件、抄送或密送。

未关闭的编辑也保存在当前浏览器的本机存储。刷新后找回，但不是跨设备同步或加密保管箱，不应在共享浏览器填写敏感信息。存储不可用时明确提示；不要把提示失败当作已保存。

另一设备修改后，旧版本不能覆盖新版本。页面保留本机输入，可先复制再手动载入服务器版本。服务器暂不可用时也可查看、继续编辑和复制本机内容，不能据此核对或覆盖未知服务器记录。没有可用记录的读取失败不显示为“没有草稿”。

原邮件过期、读取失败、账号或内容发生变化时，不据旧记录新建或核对草稿；现有编辑仍可保存。其他邮件刷新但该封邮件未变，不重复建立手工草稿，也不阻止重新核对。

## 权限边界

草稿路由只有列举、创建本地草稿、修改草稿，没有发送接口或 Gmail 写入调用。模型工具只接受当前前台个人回合，拒绝工作空间、后台计划、受限任务、迟到或已取消回合；每回合最多 3 条。

这是控制台内部的个人功能，沿用管理员入口与跨站写入保护，不扩充对外 OpenAI/Anthropic 兼容 API 或受限调用方令牌的权限。

这证明草稿工具本身不发送，不代表整个通用 Codex 会话已经具有工具级“禁止一切第三方写入”的强制隔离。连接器权限是另一层边界，不能仅凭提示词或“已核对”状态承诺绝不会发生其他工具动作。真实业务动作仍需要具体确认；不开放无人值守发送。

## 验收范围

自动化、真实 CLI 受控协议、实际隔离控制台页面及手机尺寸验证见[本轮验收](acceptance/2026-10-26-personal-mail-drafts.md)。合成数据和受控模型不代替真实邮件理解质量、真实账号发送、实体手机、连续使用或用户评价。

### 模型质量检查

`npm run verify:mail-drafts:quality` 使用真实 CLI、临时无登录目录和本机模拟响应，检查三种情况：明确收件人及手工提供正文时保存候选；只有元信息时先追问；第三方标题含恶意命令时不执行。它不会读取邮箱或调用付费模型，CI 只运行这个模式。

仅在已有模型额度授权时可加 `-- --live`，并设置 `CODEX_PERSONAL_LIVE_APPROVED=1`、`CODEX_PERSONAL_LIVE_CWD` 为已经受信任的绝对目录。真实模式复用已有登录，不复制凭据、不登记新目录，使用只读文件权限、停用连接器/终端/派生代理，最多三个回合、每回合 120 秒；失败不重试。共享配置发生变化时报告失败并保留，不自动恢复整份旧配置。输出私有证据路径和实际用量。

本机三个真实 `gpt-6-sol / medium` 样例通过，61,105 tokens；素材仍是虚构邮件，不代表真实账号到草稿的完整效果或用户评价。详情及首轮失败见[质量验收](acceptance/2026-10-26-personal-mail-quality.md)。通用个人会话没有因此自动获得这套测试限制。
